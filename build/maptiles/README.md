# Basemap tiles

Builds `public/map/world.pmtiles`, the vector basemap every map surface draws.

## Running it

```
make map-tiles
```

That builds a container pinning tippecanoe and runs `build.sh` inside it. The
container is the only place the toolchain is required: it is **not** a CI
dependency and `make test` never invokes it. Run this only when the sources or
the build flags change, and commit the result.

## What it reads

Two source sets. The four Natural Earth 110m files already committed under
`build/mapdata/source/`, which the country-lookup generator needs anyway and
which carry the label anchors (`ADMIN`, `LABEL_X`, `LABEL_Y`, `LABELRANK`). And
twelve 50m and 10m files under `build/maptiles/source/`, which are **not**
committed: 180 MB of GeoJSON, fetched by `make map-sources` and pinned by digest
in `sources.lock`.

So **run `make map-sources` before `make map-tiles` on a fresh checkout.** The
pipeline needs the network once. The plugin never does.

`build/mapdata/` is a separate generator with a separate output (`admin.go`, the
country polygons the Region lookup uses). The two share source files and nothing
else.

## What it writes

`public/map/fonts/NotoSans-Regular/` holds five signed-distance-field glyph
ranges, generated by `glyphs.js` from the `fonts-noto-core` package inside
the container. `make bundle` checks for all five by name, because a range that
goes missing from a release has no symptom except features that stop being
named. The font is not downloaded: it comes from the pinned base image,
which is also where its licence text comes from.

MapLibre resolves `glyphs` as a URL, so without these the labels have no
typeface to be drawn in. `public/map/fonts/LICENSE.txt` ships beside them
because SIL OFL 1.1 requires the notice to travel with any Modified Version, and
SDF ranges generated from a TTF are one. Noto declares no Reserved Font Name,
which is what allows the generated ranges to keep the `NotoSans-Regular` name.

One archive, ten layers, z0 through z9. `MAXZ` at the top of `build.sh` is the
ceiling, written once: every run that reaches it reads that variable, so the
depth cannot move for one layer and miss another. It must move with `MAX_ZOOM`
in `webapp/src/decorators/location/map/span.ts`, and
`TestArchiveDepthMatchesTheCameraCeiling` is what holds the two together.

| Layer | Geometry | Zooms | Attributes |
|---|---|---|---|
| `land`, `lakes` | polygons | z0-9 | none |
| `boundary_lines` | lines | z0-9 | none |
| `country_labels` | points | z0-9 | `name`, `rank` |
| `rivers`, `admin_1_lines` | lines | z4-9 | none |
| `urban_areas` | polygons | z5-9 | none |
| `roads` | lines | z5-9 | `scalerank` |
| `railroads` | lines | z5-9 | none |
| `populated_places` | points | z3-9 | `name_en`, `scalerank` |
| `airports`, `admin_1_labels` | points | z5-9 | `name`, `scalerank` |

Layers held back to a higher zoom are held back for two reasons at once. Below
that zoom they are a smear rather than information, and every layer present in a
tile costs about 40 bytes of framing before a single coordinate, against a tile
count that quadruples with every level.

## Two things in here are decisions, not mechanics

**Every country gets a label.** `labels.py` applies no `LABELRANK` cutoff and
fails the build if any admin-0 feature is dropped. The only feature above rank 6
is Western Sahara, so any cutoff omits exactly one country and that country is a
disputed territory. It would also put the label set out of step with the Region
row, which names a country from `ADMIN` over this same feature set. Density is
the renderer's collision index's job, and `rank` is carried through as a draw
priority for it.

`--drop-rate=1` exists for the same reason: tippecanoe's default drops points at
low zoom, which left one label of 177 in the z0 tile.

**Layers keep only what the style draws with.** `strip.py` takes a keep-list and
drops everything else. Lakes carry 37
fields and boundary lines 38, none of which the style reads, and among the
boundary-line fields are 34 `FCLASS_*` columns holding Natural Earth's
per-country classifications of disputed boundaries. This plugin takes no
position on those, and not shipping the data is how you take no position.
Stripping them cut the first archive by 45%.

Two fields survive that rule. `roads` keeps `scalerank`, which widens the roads
worth following and holds the minor ones back until a reader is close.
`populated_places` keeps `name_en` and `scalerank`. The name comes from Natural
Earth's English field rather than the local one because the bundled glyphs are
Latin: a local-language name would need Cyrillic, Arabic and CJK ranges, and a
CJK face alone is larger than this whole archive.

**Airports keep `NAME`, not `NAME_EN`.** Both are Latin across all 893 features,
so the reason is not the glyph one that decided `populated_places`: `NAME` is
`Sahnewal` where `NAME_EN` is `Sahnewal Airport`, and the second word is already
said by the symbol it sits under.

**Admin-1 labels come from `ne_10m_admin_1_label_points`, not from the polygon
set.** The polygons are about 39 MB and nothing here styles them; the label
points are about 4 MB and carry the anchor Natural Earth chose. They are the
reason `glyphs.js` grew a fifth range: 80 of the 11,291 names use Latin Extended
Additional, which is almost entirely Vietnamese province names, and a missing
range costs the whole label rather than its accents.

**A third decision is unresolved and is not this generator's to make.** Both
boundary layers classify their lines, and neither classification ships. Among the
515 admin-0 boundaries are ten `Line of control (please verify)`, thirty-nine
`Disputed` and four `Indeterminant frontier`, which today draw in the same
stroke as the France-Germany border. Stripping the field is not neutrality
there, it is an assertion that the lines are the same kind of thing. See the
Mapping section of the root CLAUDE.md.

## Shape of the archive

`build.sh` produces, and the reader is entitled to assume:

- PMTiles spec version 3, tile type MVT
- clustered, gzip tile compression
- zoom 0 through 9

It **used** to carry a single root directory and no leaves, which kept a
from-scratch reader down to a header parse, one directory decode and an inflate.
Extending to z8 ended that: past roughly 8,000 directory entries the writer
partitions into leaf directories, and there is no flag to prevent it. Avoiding
it would mean capping zoom or dropping layers, so the guarantee was given up
deliberately. The fallback reader now needs a second directory level, and a cold
tile lookup can take two range requests instead of one.
