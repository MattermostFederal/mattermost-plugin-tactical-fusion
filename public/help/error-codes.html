Error Codes

Every failure message and every log line carries a TF-NNNN identifier.

The point is that the code a reader sees in the sidebar and the code an operator greps out of the server log are the same one. Wording can be improved without the code moving. Quote it in a report, with the plugin version, and it names the exact branch that fired.

Codes are allocated in thousand-wide ranges, one per source file, and drift out of source order as a file grows. They are not permanent: a number can be renumbered, and a retired one can come back meaning something else. Read a code against the release it came from, and quote the plugin version alongside it when reporting one.

Looking for a fix rather than a definition? Start at Troubleshooting, which maps symptoms onto causes.

Activation 10000 to 10999

CodeName and levelMeaning
TF-10000 PluginRegistryFailed Error A decorator could not be registered, so the plugin has no registry and refuses to start. Two decorators claiming the same type, or one with an empty type, are the only ways to reach this.
TF-10001 PluginCommandRegistrationFailed Error The /tactical-fusion slash command could not be registered, so the plugin refuses to start. Usually another plugin has already claimed the trigger word.

Message decoration 11000 to 11999

CodeName and levelMeaning
TF-11000 HooksDecoratePanic Warn A decorator panicked while decorating a message. The panic was recovered and the post was left exactly as written. A bug here must never stop somebody from posting.
TF-11001 HooksDecorationTooLong Warn Decorating would have pushed the message over the maximum post size, so it was posted undecorated. See why a time was not linked.
TF-11002 HooksCotPanic Warn Reading a Cursor on Target event panicked. The panic was recovered, the post was left exactly as written, and ordinary decoration still ran.
TF-11003 HooksCotFileUnreadable Warn An attached file could not be described or read, so the post was left as an ordinary message. Check that file storage is reachable.
TF-11006 HooksCotFileNotOwned Warn An attached file was read from storage but does not belong to the post: somebody else uploaded it, it is already carried by another post, or it has been deleted. It was left unread and the post went out as an ordinary message. The line carries the file id and the poster, because unlike TF-11003 this is not an infrastructure failure and repeated occurrences are worth looking at.
TF-11004 HooksCotPropsTooLarge Warn The parsed event, together with whatever else was already attached to the post, would have exceeded what the server accepts, so nothing was rendered rather than risking a post the server would refuse.
TF-11005 HooksCotUnreadable Warn A fenced block the author labeled cot could not be read as a Cursor on Target event, so it was left as an ordinary code block. The author is told, and nobody else sees the notice.
TF-11007 HooksCotDetailDropped Warn The parsed event carried more <detail> than the post's props map had room for, so the card was rendered without the extension rows rather than not rendered at all. Position, timing, accuracy, callsign, team and remarks are unaffected, and the whole event is still readable under "As posted" in the sidebar.
TF-11008 HooksCotPropsUnmeasurable Warn Something already attached to the post could not be converted to JSON, so the size of the post's properties could not be checked and nothing was rendered. This is not caused by the event and cannot be fixed by posting a smaller one: look for another integration writing a value it cannot serialize.

Public routing 12000 to 12999

These are rendered as a page, because this route serves browsers. All four reach a reader who followed a decorator link.

CodeName and statusMessage and meaning
TF-12000 HTTPMethodNotAllowed 405 Method not allowed. Anything other than a GET on the decorator route.
TF-12001 HTTPDecoratePathInvalid 404 Not found. The path names no decorator type, or carries more than one path segment.
TF-12002 HTTPDecoratorsNotReady 404 Not found. The request landed between the plugin loading and activation finishing. Retrying works.
TF-12003 HTTPDecoratorUnknown 404 Not found. The type is not one this build registers. A link from a newer version of the plugin, or a hand-edited URL.
TF-12005 HTTPPackagePathInvalid 404 Not found. A request under /packages that does not name one archive. A hand-edited URL.
TF-12006 HTTPPackageUnknown 404 Not found. A detail map package this install does not have. See LocationMapPackagesDir.
TF-12007 HTTPPackageUnreadable 404 Not found. A package was discovered and then could not be opened, which usually means it moved or its permissions changed between the two.
TF-12004 HTTPMapDisabled 404 Not found. The full-window map page is switched off. See EnableLocationMapPage; the coordinate's own page still carries every reading.

Authenticated API 13000 to 13999

These are returned as JSON to the sidebar, which shows the message when a save fails.

CodeName and statusMessage and meaning
TF-13000 APINotAuthorized 401 Not authorized. The request carried no Mattermost session. The decorator and map pages need one too, but they redirect to the sign-in page instead of answering this, because a person can sign in and carry on where a script cannot.
TF-13001 APINotFound 404 Not found. A path under the API that names no resource.
TF-13002 APINotReady 503 Not ready. The request landed before activation built the settings store. Retrying works.
TF-13003 APIMethodNotAllowed 405 Method not allowed. The settings resource supports GET, PUT and DELETE only.
TF-13004 APIPreferencesReadFailed 500 Could not read your settings. The KV store could not be read. Logged with the same code.
TF-13005 APIPreferencesInvalidBody 400 That is not a valid settings payload. The body was not decodable, or exceeded the size cap.
TF-13006 APIPreferencesSaveFailed 500 Could not save your settings. The KV store could not be written. Logged with the same code.
TF-13007 APIPreferencesClearFailed 500 Could not restore the defaults. The stored blob could not be deleted. Logged with the same code.
TF-13008 APIConvertInvalid 400 That is not a coordinate this plugin issued. The coordinate conversion endpoint was given a format and token that do not name a coordinate. It runs exactly the checks the coordinate page runs, so a link that renders there converts here and one that does not fails in both places. Seen in the sidebar as "Not a coordinate", which almost always means a link was edited by hand.
TF-13009 APIAirportInvalid 400 That is not an airfield code this plugin issued. The airfield endpoint was given something that is not four upper-case letters. An airfield code this build's database simply does not hold is not this: that answers normally and says the code is not in the database, so that refreshing the data cannot turn every message naming a retired code into a broken link.

Settings validation 14000 to 14999

These reach the reader verbatim, on purpose: a rejected timezone is something they can act on, and a generic "something went wrong" would not be.

CodeName and levelMessage and meaning
TF-14000 PreferencesZoneNameTooLong 400 a timezone label may be at most N characters
TF-14001 PreferencesZoneNameControlCharacters 400 a timezone label may not contain control characters. A control character would disturb the layout of its row, and no real name contains one.
TF-14002 PreferencesZoneIDMalformed 400 "..." is not a timezone identifier. The string is not shaped like one at all.
TF-14003 PreferencesZoneIDLocal 400 "Local" is not a timezone identifier. It resolves to whatever zone the server process runs in, which is not a place and can differ between nodes of one cluster.
TF-14004 PreferencesZoneIDUnknown 400 unknown timezone "...". Shaped like an identifier but naming nowhere the embedded timezone database knows.
TF-14005 PreferencesTooManyZones 400 at most N timezones may be selected. Counted after duplicates are collapsed.
TF-14006 PreferencesThresholdOutOfRange 400 the flash threshold must be between N and N minutes. Zero is not out of range: it means "use the default".
TF-14008 PreferencesRowUnknown 400 "x" is not a row of the location panel The saved view named a row this version does not have. Only reachable from a hand-written request; the editor offers one checkbox per row.
TF-14009 PreferencesSectionUnknown 400 "x" is not a section of the Cursor on Target panel The saved view named a section this version does not have. Only reachable from a hand-written request; the editor offers one checkbox per section.
TF-14007 PreferencesBlobUnreadable Warn A stored settings blob could not be parsed, so the reader was served the defaults. Not an error: view settings must never be able to take the panel down. The reader's next save replaces the blob.

Settings cache 15000 to 15999

CodeName and levelMeaning
TF-15000 PreferencesCachePublishFailed Warn A cache invalidation could not be published to the other nodes in the cluster. Delivery is best effort by design: the cost is one reader seeing a stale table until the cache expires, which does not justify failing their save.

Slash commands 16000 to 16999

CodeNameMessage
TF-16000 CommandUnknownSubcommand Unknown subcommand. Available: examples, check
TF-16001 CommandExamplesNotReady Decorators are not registered yet. Try again once the plugin has finished activating. Reached through examples.
TF-16002 CommandCheckNotReady Decorators are not registered yet. Try again once the plugin has finished activating. The same condition as TF-16001, reached through check instead.
TF-16003 CommandExamplesNothingEnabled Nothing would be decorated, so there is nothing to show. Every format is switched off, so no row of examples would become a link. It is refused privately rather than posted, since a post of nothing is a permanent record saying the plugin does nothing. See Admin settings.
TF-16004 CommandExamplesTooLong The examples do not fit in a post on this server. Every link carries the install's subpath, and a long enough one pushes a message past the maximum size. Nothing is written when this happens: the built-in help carries the same examples.
TF-16006 CommandExamplesPostFailed Could not post the examples to this channel. or N of M messages could not be posted, so the examples are incomplete. The first means nothing was written; the second means some messages landed and others did not. Both are also logged. A read-only or archived channel is the usual cause.

Decorator pages 17000 to 17999

CodeName and statusMessage and meaning
TF-17000 DTGPageParamsInvalid 400 That link is missing or has an invalid date-time group. The query string carries no usable instant. See the troubleshooting entry.
TF-17001 LocationPageParamsInvalid 400 That link is missing or has an invalid coordinate. The query string carries no usable coordinate, or the coordinate does not reproduce itself, or the copy of the author's own text does not match the coordinate it is attached to. Any one of those means the link was not written by this plugin. The map page shares this code and refuses the same links, but words it That is not a coordinate this plugin issued., so both wordings are the same failure and the same check. See the troubleshooting entry.
TF-17002 AirportPageInvalid 400 That is not an airfield code this plugin issued. The airfield page was given a v parameter that is not four upper-case letters, which means the link was not written by this plugin. A code that is well formed but absent from this build's database renders the page with a note instead.

Detail map packages 18000 to 18999

These are logged rather than shown to a reader. A package that is skipped draws nothing, which on screen is indistinguishable from an area nobody built, so the log line is the only thing that will ever explain it.

CodeName and statusMessage and meaning
TF-18000 PackagesNoBundlePath log The plugin cannot locate its own bundle, so no bundled package is served. Packages in LocationMapPackagesDir are unaffected.
TF-18001 PackagesBadName log A file in a package directory is not named <command>-<area>.pmtiles. The name reaches a URL, so it is checked against a whitelist rather than cleaned. Rename it.
TF-18003 PackagesUploadBadName 400 An upload whose file is not named <command>-<area>.pmtiles. The name is what the area is keyed on, so it comes from the file rather than a field.
TF-18004 PackagesUploadNoDir 400 An upload with no LocationMapPackagesDir set. A map archive is served by byte range, so there is nowhere else it could go.
TF-18005 PackagesUploadTooLarge 400 An upload past what this route carries. Copy larger areas into the package directory instead; an upload also crosses the server's own request limits.
TF-18006 PackagesUploadNotAnArchive 400 An upload that is not a map archive built for the seam. Checked before the file is put in place, so a bad upload is refused with a reason rather than accepted and then skipped.
TF-18007 PackagesUploadWriteFailed 400 The package directory could not be written to. Check it exists and that the Mattermost process owns it.
TF-18002 PackagesBadArchive log A file is not the map archive it claims to be, or does not begin at zoom 10, where the detail tier takes over. A half-copied file, a truncated download, or an archive built to the wrong depth.
TF-18008 PackagesSchemaMismatch log A well formed archive built for a different map schema. The message says which way round it is: an older archive is re-downloaded for the area, and a newer one means this plugin is behind the archive and should be upgraded. Areas are otherwise portable across plugin versions, so this only appears when the map data itself changed shape.
