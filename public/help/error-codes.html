Error Codes

Every failure message and every log line carries a TF-NNNN identifier.

The point is that the code a reader sees in the sidebar and the code an operator greps out of the server log are the same one. Wording can be improved without the code moving. Quote it in a report, with the plugin version, and it names the exact branch that fired.

Codes are allocated in thousand-wide ranges, one per source file, and drift out of source order as a file grows. They are not permanent: a number can be renumbered, and a retired one can come back meaning something else. Read a code against the release it came from, and quote the plugin version alongside it when reporting one.

Looking for a fix rather than a definition? Start at Troubleshooting, which maps symptoms onto causes.

Activation 10000 to 10999

CodeName and levelMeaning
TF-10000 PluginRegistryFailed Error A decorator could not be registered, so the plugin has no registry and refuses to start. Two decorators claiming the same type, or one with an empty type, are the only ways to reach this.
TF-10001 PluginCommandRegistrationFailed Error The /tactical-fusion slash command could not be registered, so the plugin refuses to start. Usually another plugin has already claimed the trigger word.

Message decoration 11000 to 11999

CodeName and levelMeaning
TF-11000 HooksDecoratePanic Warn A decorator panicked while decorating a message. The panic was recovered and the post was left exactly as written. A bug here must never stop somebody from posting.
TF-11001 HooksDecorationTooLong Warn Decorating would have pushed the message over the maximum post size, so it was posted undecorated. See why a time was not linked.
TF-11002 HooksCotPanic Warn Reading a Cursor on Target event panicked. The panic was recovered, the post was left exactly as written, and ordinary decoration still ran.
TF-11003 HooksCotFileUnreadable Warn An attached file could not be described or read, so the post was left as an ordinary message. Check that file storage is reachable.
TF-11006 HooksCotFileNotOwned Warn An attached file was read from storage but does not belong to the post: somebody else uploaded it, it is already carried by another post, or it has been deleted. It was left unread and the post went out as an ordinary message. The line carries the file id and the poster, because unlike TF-11003 this is not an infrastructure failure and repeated occurrences are worth looking at.
TF-11004 HooksCotPropsTooLarge Warn The parsed event, together with whatever else was already attached to the post, would have exceeded what the server accepts, so nothing was rendered rather than risking a post the server would refuse.
TF-11005 HooksCotUnreadable Warn A fenced block the author labeled cot could not be read as a Cursor on Target event, so it was left as an ordinary code block. The author is told, and nobody else sees the notice.
TF-11007 HooksCotDetailDropped Warn The parsed event carried more <detail> than the post's props map had room for, so the card was rendered without the extension rows rather than not rendered at all. Position, timing, accuracy, callsign, team and remarks are unaffected, and the whole event is still readable under "As posted" in the sidebar.
TF-11008 HooksCotPropsUnmeasurable Warn Something already attached to the post could not be converted to JSON, so the size of the post's properties could not be checked and nothing was rendered. This is not caused by the event and cannot be fixed by posting a smaller one: look for another integration writing a value it cannot serialize.
TF-11016 HooksAirfieldsPropsUnmeasurable warn the post's props could not be measured; posting unstamped A message of nothing but airfield codes was about to get its route map, but something already on the post's props would not encode, so the size gate could not run. The links are written and the map is not. Not the author's doing: the value that will not encode came from elsewhere on the post.
TF-11017 HooksAirfieldsPropsTooLarge warn the parsed document would exceed the maximum post props size; posting unstamped The route's props, added to what the post already carried, would cross the props budget. The links are written and the map is not. A route of up to 64 airfields fits on its own; this fires when another integration has already filled most of the budget.
TF-11018 HooksAvReportPanic warn recovered from panic while reading an aviation report; post left unmodified The report decoder panicked. The post goes out with the message as written and no card, and decoration of the rest of the message still runs. The recover is the one all three card formats share; a panic here is a bug, so report the log line.
TF-11019 HooksAvReportUnreadable warn an aviation report could not be read; posting unstamped A fenced block labeled metar, speci, taf or notam did not decode. The author is told the same in a message only they see. A multi-line message with no label that fails to decode is left alone silently and logs nothing, because ordinary text reaches that reader constantly.
TF-11020 HooksAvReportPropsUnmeasurable warn the post's props could not be measured; posting unstamped A report was about to get its card, but something already on the post's props would not encode, so the size gate could not run. The author is told. The value that will not encode came from elsewhere on the post.
TF-11021 HooksAvReportPropsTooLarge warn the parsed document would exceed the maximum post props size; posting unstamped Even with the decoded rows dropped, the report's props would cross the props budget, so the post goes out as ordinary text and the author is told. A report on its own always fits; this fires when another integration has already filled most of the budget.
TF-11022 HooksAvReportRowsDropped warn the decoded report carried more rows than the post props map has room for; stamping without them The card was rendered on its lower rung: the report as posted, its summary and its station are kept, and the decoded rows, periods, remarks and undecoded groups are dropped. The card says so.
TF-11009 HooksGeoJSONPanic Warn Reading a GeoJSON document panicked. The post was created unchanged, so nothing was lost, but the document was not rendered. Please report it with the message that caused it.
TF-11010 HooksGeoJSONUnreadable Warn A fenced block the author labeled geojson could not be read as a GeoJSON document, so it was left as an ordinary code block. The author is told, and nobody else sees the notice. The commonest causes are a document over 64 KB, more than 256 features, or more than 4096 coordinates.
TF-11011 HooksGeoJSONPropsTooLarge Warn The parsed document would not fit in the post's properties even with the feature properties dropped, so the post was left as ordinary text. Post a smaller document, or attach the file rather than pasting it.
TF-11012 HooksGeoJSONPropsUnmeasurable Warn Something already attached to the post could not be converted to JSON, so the size of the post's properties could not be checked and nothing was rendered. This is not caused by the document and cannot be fixed by posting a smaller one: look for another integration writing a value it cannot serialize.
TF-11013 HooksGeoJSONPropertiesDropped Warn The parsed document carried more feature properties than the post's props map had room for, so the card was rendered without them rather than not rendered at all. The feature names, geometry and counts are unaffected, and the whole document is still readable under "As posted" in the sidebar.
TF-11014 HooksGeoJSONFileUnreadable Warn An attachment offered to the GeoJSON reader could not be read from file storage, so the post was left as ordinary text. Attachments fail silently to the author, so this is the only record.
TF-11015 HooksGeoJSONFileNotOwned Warn An attachment offered to the GeoJSON reader was not the poster's own, is already attached to another post, or has been deleted, so it was left alone. This is the check that stops a post quoting somebody else's file into its own properties.

Public routing 12000 to 12999

These are rendered as a page, because this route serves browsers. All four reach a reader who followed a decorator link.

CodeName and statusMessage and meaning
TF-12000 HTTPMethodNotAllowed 405 Method not allowed. Anything other than a GET on the decorator route.
TF-12001 HTTPDecoratePathInvalid 404 Not found. The path names no decorator type, or carries more than one path segment.
TF-12002 HTTPDecoratorsNotReady 404 Not found. The request landed between the plugin loading and activation finishing. Retrying works.
TF-12003 HTTPDecoratorUnknown 404 Not found. The type is not one this build registers. A link from a newer version of the plugin, or a hand-edited URL.
TF-12005 HTTPPackagePathInvalid 404 Not found. A request under /packages that does not name one archive. A hand-edited URL.
TF-12006 HTTPPackageUnknown 404 Not found. A detail map package this install does not have. See LocationMapPackagesDir.
TF-12007 HTTPPackageUnreadable 404 Not found. A package was discovered and then could not be opened, which usually means it moved or its permissions changed between the two.
TF-12009 HTTPMapAirportUnavailable 404 There is no map here. The one answer /map?airport= gives for every way it can decline: a value that is not four upper-case letters, and an airfield code this build's database does not hold. One code, as the post address has one, so the address cannot be used to probe the database a code at a time.
TF-12008 HTTPMapPostUnavailable 404 There is no map here. The one answer /map?post= gives for every way it can decline: no such post, a post in a channel you may not read, a post this plugin never rendered, and a post whose card has stood down because it was edited or its attachment is gone. They are deliberately one code, so the address cannot be used to find out which.
TF-12004 HTTPMapDisabled 404 Not found. The full-window map page is switched off. See EnableLocationMapPage; the coordinate's own page still carries every reading.

Authenticated API 13000 to 13999

These are returned as JSON to the sidebar, which shows the message when a save fails.

CodeName and statusMessage and meaning
TF-13000 APINotAuthorized 401 Not authorized. The request carried no Mattermost session. The decorator and map pages need one too, but they redirect to the sign-in page instead of answering this, because a person can sign in and carry on where a script cannot.
TF-13001 APINotFound 404 Not found. A path under the API that names no resource.
TF-13002 APINotReady 503 Not ready. The request landed before activation built the settings store. Retrying works.
TF-13003 APIMethodNotAllowed 405 Method not allowed. The settings resource supports GET, PUT and DELETE only.
TF-13004 APIPreferencesReadFailed 500 Could not read your settings. The KV store could not be read. Logged with the same code.
TF-13005 APIPreferencesInvalidBody 400 That is not a valid settings payload. The body was not decodable, or exceeded the size cap.
TF-13006 APIPreferencesSaveFailed 500 Could not save your settings. The KV store could not be written. Logged with the same code.
TF-13007 APIPreferencesClearFailed 500 Could not restore the defaults. The stored blob could not be deleted. Logged with the same code.
TF-13008 APIConvertInvalid 400 That is not a coordinate this plugin issued. The coordinate conversion endpoint was given a format and token that do not name a coordinate. It runs exactly the checks the coordinate page runs, so a link that renders there converts here and one that does not fails in both places. Seen in the sidebar as "Not a coordinate", which almost always means a link was edited by hand.
TF-13009 APIAirportInvalid 400 That is not an airfield code this plugin issued. The airfield endpoint was given a v that is not four upper-case letters or an i that is not three. An airfield code this build's database simply does not hold is not this: that answers normally and says the code is not in the database, so that refreshing the data cannot turn every message naming a retired code into a broken link.
TF-13010 APIAirportParamsConflict 400 An airfield link names exactly one code. The request carried both v (an ICAO ident) and i (an IATA code), or neither. A link this plugin writes carries one of the two, so a request with both was assembled by hand and the two could disagree about which airfield is meant.
TF-13011 APIAvReportInvalid 400 That is not an aviation report this plugin issued. The report endpoint was given a v that does not decode as a report, or a t that does not reproduce the report's own day, hour and minute. A link this plugin writes always does both, so the link was edited by hand.
TF-13012 APICyberInvalid 400 That is not an indicator this plugin issued. The cyber endpoint was given a kind and value that do not reproduce each other, which means the link was not written by this plugin. An indicator no dataset holds is not this: that answers normally and says so, exactly as the page does.

Settings validation 14000 to 14999

These reach the reader verbatim, on purpose: a rejected timezone is something they can act on, and a generic "something went wrong" would not be.

CodeName and levelMessage and meaning
TF-14000 PreferencesZoneNameTooLong 400 a timezone label may be at most N characters
TF-14001 PreferencesZoneNameControlCharacters 400 a timezone label may not contain control characters. A control character would disturb the layout of its row, and no real name contains one.
TF-14002 PreferencesZoneIDMalformed 400 "..." is not a timezone identifier. The string is not shaped like one at all.
TF-14003 PreferencesZoneIDLocal 400 "Local" is not a timezone identifier. It resolves to whatever zone the server process runs in, which is not a place and can differ between nodes of one cluster.
TF-14004 PreferencesZoneIDUnknown 400 unknown timezone "...". Shaped like an identifier but naming nowhere the embedded timezone database knows.
TF-14005 PreferencesTooManyZones 400 at most N timezones may be selected. Counted after duplicates are collapsed.
TF-14006 PreferencesThresholdOutOfRange 400 the flash threshold must be between N and N minutes. Zero is not out of range: it means "use the default".
TF-14008 PreferencesRowUnknown 400 "x" is not a row of the location panel The saved view named a row this version does not have. Only reachable from a hand-written request; the editor offers one checkbox per row.
TF-14009 PreferencesSectionUnknown 400 "x" is not a section of the Cursor on Target panel The saved view named a section this version does not have. Only reachable from a hand-written request; the editor offers one checkbox per section.
TF-14007 PreferencesBlobUnreadable Warn A stored settings blob could not be parsed, so the reader was served the defaults. Not an error: view settings must never be able to take the panel down. The reader's next save replaces the blob.

Settings cache 15000 to 15999

CodeName and levelMeaning
TF-15000 PreferencesCachePublishFailed Warn A cache invalidation could not be published to the other nodes in the cluster. Delivery is best effort by design: the cost is one reader seeing a stale table until the cache expires, which does not justify failing their save.

Slash commands 16000 to 16999

CodeNameMessage
TF-16000 CommandUnknownSubcommand Unknown subcommand. Available: examples, check
TF-16001 CommandExamplesNotReady Decorators are not registered yet. Try again once the plugin has finished activating. Reached through examples.
TF-16002 CommandCheckNotReady Decorators are not registered yet. Try again once the plugin has finished activating. The same condition as TF-16001, reached through check instead.
TF-16003 CommandExamplesNothingEnabled Nothing would be decorated, so there is nothing to show. Every format is switched off, so no row of examples would become a link. It is refused privately rather than posted, since a post of nothing is a permanent record saying the plugin does nothing. See Admin settings.
TF-16004 CommandExamplesTooLong The examples do not fit in a post on this server. Every link carries the install's subpath, and a long enough one pushes a message past the maximum size. Nothing is written when this happens: the built-in help carries the same examples.
TF-16006 CommandExamplesPostFailed Could not post the examples to this channel. or N of M messages could not be posted, so the examples are incomplete. The first means nothing was written; the second means some messages landed and others did not. Both are also logged. A read-only or archived channel is the usual cause.
TF-16007 CommandNoteUsage Usage: /tactical-fusion note <label> | <markdown>. note needs a label, a |, and some markdown. The label is one line and may not contain |, since the first | is where the markdown starts.
TF-16008 CommandNoteInvalid A note is up to 1000 characters of markdown. The markdown is longer than a note may carry. Split it into two notes, or post it as a message.
TF-16009 CommandNoteTooLong That note does not fit in a post once it is written into a link. The markdown travels URL-encoded, which can triple its length, and non-Latin text grows more. Nothing was posted.
TF-16010 CommandNotePostFailed Could not post the note to this channel. Also logged. A read-only or archived channel is the usual cause.
TF-16011 CommandPostNotPermitted You cannot post in this channel, so this command cannot post for you. examples and note post as you, so each first checks that you may post in the channel. A read-only or moderated channel is the usual cause. Nothing was posted.
TF-16012 CommandExamplesUnknownOption Unknown option. Run examples on its own to post them, examples --raw to post them as text to copy, or examples --mcp to post questions for the @fusion agent. examples was given something other than --raw or --mcp. Nothing was posted.

Decorator pages 17000 to 17999

CodeName and statusMessage and meaning
TF-17000 DTGPageParamsInvalid 400 That link is missing or has an invalid date-time group. The query string carries no usable instant. See the troubleshooting entry.
TF-17001 LocationPageParamsInvalid 400 That link is missing or has an invalid coordinate. The query string carries no usable coordinate, or the coordinate does not reproduce itself, or the copy of the author's own text does not match the coordinate it is attached to. Any one of those means the link was not written by this plugin. The map page shares this code and refuses the same links, but words it That is not a coordinate this plugin issued., so both wordings are the same failure and the same check. See the troubleshooting entry.
TF-17002 AirportPageInvalid 400 That is not an airfield code this plugin issued. The airfield page was given a v parameter that is not four upper-case letters or an i parameter that is not three, which means the link was not written by this plugin. A code that is well formed but absent from this build's database renders the page with a note instead.
TF-17003 AirportPageParamsConflict 400 An airfield link names exactly one code. The page was asked for both an ICAO ident and an IATA code, or for neither. The same rule TF-13010 applies on the API: a link carries one code, so two of them cannot be trusted to agree.
TF-17004 AvReportPageInvalid 400 That is not an aviation report this plugin issued. The report page was given a v that does not decode or a t that does not reproduce the report's time group. The same rule TF-13011 applies on the API.
TF-17005 FrequencyPageInvalid 400 That is not a frequency this plugin issued. The frequency page was given a v the grammar would not have produced, or one outside 2 MHz to 1,300 MHz once its unit is applied. A link this plugin writes always passes both, so the link was edited by hand.
TF-17006 NotePageInvalid 400 That is not a note this plugin issued. The note page was given no v, a blank one, or one longer than 1,000 characters. A link this plugin writes always passes, so the link was edited by hand.
TF-17007 CyberPageInvalid 400 That is not an indicator this plugin issued. The cyber page was given a kind and value that do not reproduce each other, which means the link was not written by this plugin. An indicator no dataset describes renders the page with a note instead.

Detail map packages 18000 to 18999

These are logged rather than shown to a reader. A package that is skipped draws nothing, which on screen is indistinguishable from an area nobody built, so the log line is the only thing that will ever explain it.

CodeName and statusMessage and meaning
TF-18000 PackagesNoBundlePath log The plugin cannot locate its own bundle, so no bundled package is served. Packages in LocationMapPackagesDir are unaffected.
TF-18001 PackagesBadName log A file in a package directory is not named <command>-<area>.pmtiles. The name reaches a URL, so it is checked against a whitelist rather than cleaned. Rename it.
TF-18003 PackagesUploadBadName 400 An upload whose file is not named <command>-<area>.pmtiles. The name is what the area is keyed on, so it comes from the file rather than a field.
TF-18004 PackagesUploadNoDir 400 An upload with no LocationMapPackagesDir set. A map archive is served by byte range, so there is nowhere else it could go.
TF-18005 PackagesUploadTooLarge 400 An upload past what this route carries. Copy larger areas into the package directory instead; an upload also crosses the server's own request limits.
TF-18006 PackagesUploadNotAnArchive 400 An upload that is not a map archive built for the seam. Checked before the file is put in place, so a bad upload is refused with a reason rather than accepted and then skipped.
TF-18007 PackagesUploadWriteFailed 400 The package directory could not be written to. Check it exists and that the Mattermost process owns it.
TF-18002 PackagesBadArchive log A file is not the map archive it claims to be, or does not begin at zoom 10, where the detail tier takes over. A half-copied file, a truncated download, or an archive built to the wrong depth.
TF-18008 PackagesSchemaMismatch log A well formed archive built for a different map schema. The message says which way round it is: an older archive is re-downloaded for the area, and a newer one means this plugin is behind the archive and should be upgraded. Areas are otherwise portable across plugin versions, so this only appears when the map data itself changed shape.

Plugin bridge 19000 to 19999

Answers to another plugin calling Tactical Fusion, either server to server through /bridge/v1 or from a browser through /api/v1/decorate and /api/v1/link. Every refusal below is JSON carrying message, code and, for a declined link, reason; a successful answer has its own shape. See Plugin Integration.

CodeName and levelMeaning
TF-19000 BridgeNotAuthorized 401 Not authorized. A request reached /bridge/v1 without the Mattermost-Plugin-ID header. Mattermost sets that header only on a request another plugin sends through PluginHTTP, and strips it from anything a browser sends, so a browser always gets this. A webapp uses /api/v1 instead.
TF-19001 BridgeNotFound 404 Not found. A path under /bridge/v1 that names no operation. The operations are decorate, link and info.
TF-19002 BridgeMethodNotAllowed 405 Method not allowed. decorate and link take POST; info takes GET.
TF-19003 BridgeInvalidBody 400 That is not a valid request body. The body is not JSON, is larger than 64 KB, or is a link request whose label contains a line break, which the message says separately.
TF-19004 BridgeNotReady 503 Not ready. The request landed before activation finished or before the plugin configuration loaded. Retrying works.
TF-19005 BridgeUnknownType 422 Unknown decorator type. A link request named a type other than dtg, location or airport. Reason unknown_type.
TF-19006 BridgeTokenNotRecognized 422 The token is not one this decorator type reads. The token is not a value of that type with every format switched on: a J date-time group, a coordinate short of the required decimal places, an airfield code the database does not hold, or a token still carrying its field label. Reason not_recognized.
TF-19007 BridgeFormatDisabled 422 The token's format is switched off by an administrator. The token is well formed, but the format it is written in, or its whole section, is off in the admin settings. UTM is off by default, so a UTM token gets this on a default install. Reason disabled.
TF-19008 BridgePanic 500 Error Internal error. A bridge request panicked and was recovered. Logged with the same code, the path and the calling plugin's id. This is a bug worth reporting with the text that caused it.

Agents MCP server 20000 to 20999

Answers to the Mattermost Agents plugin calling this plugin's tools over MCP at /mcp. The first five are activation, shutdown and routing, and the sixth is a tool that failed inside; the rest are a tool declining what it was asked for, which an agent sees as a failed tool call rather than as an answer.

CodeName and levelMeaning
TF-20000 MCPInitFailed Activation The MCP server could not be built, so the plugin refuses to start. The only cause is an incomplete manifest, which means the build is broken rather than the server.
TF-20001 MCPManifestIncomplete Activation The plugin manifest is missing its id, version or name. The reason behind TF-20000, and a packaging bug rather than anything an administrator can change.
TF-20002 MCPRegistrationFailed Warn Registering with the Agents plugin did not succeed. Activation continues: everything except the MCP tools is unaffected. Usually means the Agents plugin is not installed, not enabled, or still starting. Registration retries on its own, and is attempted again whenever this plugin re-activates.
TF-20003 MCPUnregisterFailed Warn Telling the Agents plugin to drop this server on shutdown did not succeed, so it may keep offering tools that are no longer there until it is restarted or this plugin re-activates. Shutdown continues.
TF-20004 MCPNotReady 503 Not ready. An MCP request landed before activation finished or before the plugin configuration loaded. Retrying works.
TF-20005 MCPToolPanic Error Internal error. A tool call panicked and was recovered. Logged with the same code and the tool's name. This is a bug worth reporting with the arguments that caused it.
TF-20006 MCPLinkDeclined Tool error The link_token tool was given a type it does not know, a token that type does not read, or a token whose format an administrator has switched off. It carries the same wording as the matching 19005 to 19007 refusal, because it is the same operation on a different transport.
TF-20007 MCPConvertInvalid Tool error That is not a coordinate this plugin issued. The convert_coordinate tool was given a format and value that do not validate together, the same check /api/v1/convert applies.
TF-20008 MCPAirportInvalid Tool error That is not an ICAO identifier or IATA code. The lookup_airfield tool was given a value that is not the shape of an ICAO identifier or an IATA code. A well-shaped code the database does not hold is not this: that answers found: false.
TF-20009 MCPAvReportInvalid Tool error That is not a METAR, SPECI, TAF or NOTAM this plugin reads. The decode_aviation_report tool was given text that does not start like a report, holds more than one, or is longer than a report can be.
TF-20010 MCPCotInvalid Tool error That is not a Cursor on Target event this plugin reads: ... The decode_cot tool was given XML the event reader refused. The message ends with the reason, such as a missing uid or an event too large.
TF-20011 MCPGeoJSONInvalid Tool error That is not a GeoJSON document this plugin reads: ... The summarize_geojson tool was given JSON that is not GeoJSON, or a document past this build's size, feature or position limits. The message ends with the reason.
TF-20012 MCPFrequencyInvalid Tool error That is not a frequency between 2 MHz and 1,300 MHz this plugin reads. The describe_frequency tool was given something that is not a frequency, or one outside that range once its unit is applied.
TF-20013 MCPDateTimeInvalid Tool error That is not a date-time group or RFC 3339 timestamp this plugin reads. The read_date_time tool was given text in neither form.
TF-20014 MCPCreateCotInvalid Tool error Could not build that event: ... The create_cot tool was missing a callsign, given a position off the globe, an affiliation or dimension it does not know, a malformed type, a stale time over a week, or remarks over 256 characters. The message ends with which.
TF-20015 MCPCreateGeoJSONInvalid Tool error Could not build that document: ... The create_geojson tool was given no features or too many, a feature with no name, the wrong number of positions for its kind, a position off the globe, or a color that is not #rrggbb. The message ends with which feature and why.
TF-20016 MCPCyberInvalid Tool error Give between 1 and 25 indicators. The lookup_cyber_indicator tool was given no indicators, or more than 25. An indicator in the list that is not a CVE, CWE, ATT&CK id, IP address or file hash is not this: it is answered as not recognized, and the others in the list are still looked up.

Cyber datasets 21000 to 21999

These are logged rather than shown to a reader, and logged once per file rather than once per lookup. A dataset that is skipped enriches nothing, which in the panel is indistinguishable from an indicator nothing is known about, so the log line is the only thing that will ever explain it. Skipping is per file: every other dataset still answers. See where the data comes from.

CodeName and levelMeaning
TF-21000 CyberDataNoBundlePath log The plugin cannot locate its own bundle, so the datasets shipped inside it are not read. Datasets in CyberDatasetsDir are unaffected.
TF-21001 CyberDataUnreadable log A dataset file could not be opened, or its rows are not the shape this build reads. The file is skipped and every other dataset still answers.
TF-21002 CyberDataSchemaMismatch log A dataset carries no schema stamp, or one built for a different reader. Distinct from unreadable, because the remedy is a newer dataset rather than a repaired file. See the troubleshooting entry.
TF-21003 CyberDataBadName log A file in the dataset directory is not named after a dataset this build reads. The names are cve.tsv, cvedetail.tsv, cwedetail.tsv, attackdetail.tsv, advisory.tsv, threat.tsv, malware.tsv, epss.tsv, kev.tsv, ip.tsv and watchlist.tsv. Rename it, or take it out of the directory.
TF-21004 CyberDataMMDBUnreadable log A vendor .mmdb database could not be opened, or its declared type is not one this build reads. The tabular datasets are unaffected.
TF-21005 CyberDataLookupFailed panel A dataset opened and then could not be read when somebody looked an indicator up, usually because the file was replaced or removed underneath the server. The panel says the dataset could not be read rather than that the indicator is not listed, because those are opposite answers. Put the file back, or re-copy it, and the next lookup picks it up.
TF-21006 CyberDataUnpackFailed log A gzipped dataset such as cve.tsv.gz could not be unpacked beside itself: the archive is truncated or corrupt, it unpacks to more than 2 GiB, or the server cannot write to the directory. Any cve.tsv already there is left as it was. Re-copy the archive, make the directory writable by the Mattermost server, or unpack it yourself with gunzip -k and the plugin reads the result.
