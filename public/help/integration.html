Plugin Integration

Put a Tactical Fusion link into another plugin's output, from its server or from its web app.

What you get

Another Mattermost plugin can ask Tactical Fusion for a decorator link and embed it in whatever it writes. The link is ordinary markdown, [label](url), and once rendered it behaves like one Tactical Fusion wrote into a posted message: a click that opens the sidebar panel, and a standalone page on clients without the web app, such as mobile. A hover card appears wherever Mattermost renders the markdown in a post or message, and on the Link component. Markdown your own web app renders is not yet verified to get one.

Your plugin runsUseTransport
Server side (Go): bot posts, slash commands, ephemeral messages, dialogs The Go client, bridgeclient PluginHTTP to /bridge/v1
Server side, not Go, or without the client The HTTP contract PluginHTTP to /bridge/v1
In the browser: your own components, panels, modals window.TacticalFusion The reader's session, to /api/v1
An LLM agent in the Agents plugin The MCP tools PluginHTTP to /mcp

Every transport offers the same two operations:

OperationGive itGet backUse it when
link A decorator type and one token One link You hold a structured value and know what it is: a field in a record, a column in an API response
decorate A piece of markdown text The text with every recognized token linked You produce free text, such as a generated report, and want it treated exactly like a posted message

Always have a plain-text fallback.

Tactical Fusion may not be installed, may be disabled, or may have the format switched off. Every call can decline, and the right answer in all of those cases is to show the token as plain text. Nothing here should ever stop your plugin from writing its output.

link: one token

Request fieldTypeRequiredMeaning
type string yes dtg, location, airport, avreport or frequency
token string yes The value without a field label: PHIK, not ICAO:PHIK. Leading and trailing whitespace is trimmed. See tokens
label string no The link text. Defaults to the trimmed token. Markdown characters are escaped for you. May not contain a line break
reference_time integer no Unix milliseconds. Supplies the month and year of a short date-time group such as 091630Z. Omitted or zero means now
Response fieldTypeMeaning
markdownstringThe complete link, [label](url), ready to embed
urlstringThe link destination alone. Root-relative, carrying the server's subpath if it has one
typestringThe decorator type that built it
labelstringThe link text, before markdown escaping

A token is read by the decorator you name, with no field label required, because naming the type is a stronger signal than a label. Every other rule still applies: a J date-time group is declined, a coordinate needs its decimal places, and an airfield has to be in the database.

decorate: a whole message

Request fieldTypeRequiredMeaning
message string yes Markdown text, at most 64 KB of request
reference_time integer no Unix milliseconds, as for link. Pass the time the text is about, such as the original post's create_at
Response fieldTypeMeaning
messagestringThe text with links written in
changedbooleanWhether anything was linked
fits_postbooleanWhether message fits 4,000 characters, the smallest post limit any Mattermost server enforces

This is the matcher a posted message goes through, so the rules on the Recognized Formats page apply exactly: an airfield code needs its ICAO: label, and anything inside code, links and URLs is left alone. Decorating text that is already decorated changes nothing. 

Convoy departs 141200ZSEP26 from ICAO:PHIK to 18S UJ 23478 06483

becomes

Convoy departs [141200ZSEP26](/plugins/com.mattermost.plugin-tactical-fusion/decorate/dtg?a=&dtg=141200ZSEP26&t=1789387200000&z=Z) from ICAO:[PHIK](/plugins/com.mattermost.plugin-tactical-fusion/decorate/airport?v=PHIK) to [18S UJ 23478 06483](/plugins/com.mattermost.plugin-tactical-fusion/decorate/location?f=mgrs&r=18S+UJ+23478+06483&v=18SUJ2347806483)

Links are long.

A twelve-character date-time group becomes roughly a hundred characters once linked, so text that fits in a post before decoration may not after. When fits_post is false and you are about to create a post, post your original text instead. Tactical Fusion makes the same trade for posted messages.

From your plugin's server, in Go

Import the client package that ships in the Tactical Fusion repository. It uses only the Go standard library and your plugin's existing p.API. 

go get github.com/MattermostFederal/mattermost-plugin-tactical-fusion/bridgeclient@latest
import "github.com/MattermostFederal/mattermost-plugin-tactical-fusion/bridgeclient"

func (p *Plugin) OnActivate() error {
    p.tacticalFusion = bridgeclient.NewClient(p.API)
    return nil
}

A link in a bot post

field := "PHIK"
link, err := p.tacticalFusion.Link(ctx, bridgeclient.LinkRequest{
    Type:  bridgeclient.TypeAirport,
    Token: "PHIK",
    Label: "Hickam",
})
if err == nil {
    field = link.Markdown
}

_, appErr := p.API.CreatePost(&model.Post{
    UserId:    p.botUserID,
    ChannelId: channelID,
    Message:   "Recovery field: " + field,
})

A decorated slash command reply

report := p.buildReport(args.ChannelId)

decorated, err := p.tacticalFusion.Decorate(ctx, bridgeclient.DecorateRequest{Message: report})
if err == nil && decorated.FitsPost {
    report = decorated.Message
}

return &model.CommandResponse{
    ResponseType: model.CommandResponseTypeEphemeral,
    Text:         report,
}, nil

Handling a decline

link, err := p.tacticalFusion.Link(ctx, request)
switch {
case err == nil:
    text = link.Markdown
case errors.Is(err, bridgeclient.ErrPluginNotActive),
    errors.Is(err, bridgeclient.ErrNotRecognized),
    errors.Is(err, bridgeclient.ErrDisabled):
    text = request.Token
default:
    p.API.LogWarn("Tactical Fusion link failed", "error", err.Error())
    text = request.Token
}
SentinelMeans
ErrPluginNotActiveTactical Fusion is not installed, not enabled, or gave an answer that is not its own
ErrNotRecognizedThe token is not a value of that type
ErrDisabledThe token is valid but its format is switched off
ErrUnknownTypeThe type is not dtg, location, airport, avreport or frequency

errors.As(err, &bridgeErr) with a *bridgeclient.Error gives the HTTP status, the numeric TF code, the reason and the message. client.Info(ctx) returns the plugin version, the bridge version, every decorator type and the ones an administrator has left on. The package's README.md carries more examples.

Calling the bridge over HTTP

The Go client is a thin wrapper. Any plugin can send the same requests through the plugin API's PluginHTTP. The path starts with Tactical Fusion's plugin id, and Mattermost adds the Mattermost-Plugin-ID header naming your plugin, which is how the bridge authenticates you. You cannot set that header yourself, and a browser request never carries it.

MethodPathBodyAnswers
POST /com.mattermost.plugin-tactical-fusion/bridge/v1/link A link request 200 with a link, or an error
POST /com.mattermost.plugin-tactical-fusion/bridge/v1/decorate A decorate request 200 with the decorated text, or an error
GET /com.mattermost.plugin-tactical-fusion/bridge/v1/info None 200 with plugin_version, api_version, types and enabled_types 
request, _ := http.NewRequest(http.MethodPost,
    "/com.mattermost.plugin-tactical-fusion/bridge/v1/link",
    strings.NewReader(`{"type":"airport","token":"PHIK"}`))
request.Header.Set("Content-Type", "application/json")

response := p.API.PluginHTTP(request)
if response == nil {
    return plainTextFallback
}
defer response.Body.Close()

Unknown request fields are ignored, and bodies over 64 KB are refused. A response that is not JSON with a non-zero code did not come from Tactical Fusion, usually because it is not installed or not enabled.

From your plugin's web app

Tactical Fusion's web app publishes window.TacticalFusion when it initializes. Calls go to the server with the reader's own session, so there is nothing to configure.

Waiting for it

Plugins initialize in no fixed order, so yours may run first. Listen for the tactical-fusion:ready event on window, whose detail is the API, and then check for the global. In that order, an install that lands between your first render and your listener is still seen. If neither ever arrives, Tactical Fusion is not installed and you render plain text. 

import React, {useEffect, useState} from 'react';

export function useTacticalFusion() {
    const [api, setApi] = useState(() => window.TacticalFusion);

    useEffect(() => {
        if (api) {
            return undefined;
        }
        const onReady = () => setApi(window.TacticalFusion);
        window.addEventListener('tactical-fusion:ready', onReady);
        if (window.TacticalFusion) {
            onReady();
        }
        return () => window.removeEventListener('tactical-fusion:ready', onReady);
    }, [api]);

    return api;
}

The Link component

The simplest way in, and the one to use when the hover card matters. It renders the token as plain text while it asks, the link once it has one, and your fallback (or the token) if it is declined. Results are cached for five minutes, so a list of rows naming the same field asks once. 

export const FieldCell = ({icao}: {icao: string}) => {
    const tacticalFusion = useTacticalFusion();
    if (!tacticalFusion) {
        return <span>{icao}</span>;
    }

    return (
        <tacticalFusion.Link
            type='airport'
            token={icao}
            fallback={<span>{icao}</span>}
        />
    );
};

Clicking the link opens the Tactical Fusion sidebar panel. Your plugin does not need to handle the click.

link and decorate

try {
    const link = await window.TacticalFusion.link('location', '18S UJ 23478 06483', {label: 'Rally point'});
    draft = `Meet at ${link.markdown}`;
} catch (error) {
    draft = 'Meet at 18S UJ 23478 06483';
}

A declined call rejects with an Error whose name is TacticalFusionError and which carries status, code and reason (unknown_type, not_recognized, disabled, or null for a failure that is not a decline).

To show decorate() output in your own component, render it as markdown, for example with the window.PostUtils.formatText and window.PostUtils.messageHtmlToComponent helpers Mattermost gives plugins. A click on any of the links opens the sidebar. Whether the hover card appears on links rendered that way outside a post has not been verified; use Link where it matters.

TypeScript declaration

Copy this into your plugin to type the global.

import type React from 'react';

export interface TacticalFusionLink {
    markdown: string;
    url: string;
    type: string;
    label: string;
}

export interface TacticalFusionDecorated {
    message: string;
    changed: boolean;
    fitsPost: boolean;
}

export interface TacticalFusionApi {
    readonly apiVersion: number;
    readonly version: string;
    readonly types: readonly string[];
    decorate(message: string, options?: {referenceTime?: Date | number; signal?: AbortSignal}): Promise<TacticalFusionDecorated>;
    link(type: string, token: string, options?: {label?: string; referenceTime?: Date | number; signal?: AbortSignal}): Promise<TacticalFusionLink>;
    readonly Link: React.ComponentType<{
        type: string;
        token: string;
        label?: string;
        referenceTime?: Date | number;
        fallback?: React.ReactNode;
    }>;
}

declare global {
    interface Window {
        TacticalFusion?: TacticalFusionApi;
    }
}

From an LLM agent, over MCP

The Mattermost Agents plugin discovers this plugin's operations as MCP tools and offers them to its agents, so an agent answering in a channel can decorate a message it is about to post, build one link, convert a coordinate or look up an airfield. There is nothing to configure here: the tools register themselves when Tactical Fusion activates, and an administrator enables or disables them per tool in the Agents plugin's own Tools settings.

Tool names are namespaced with this plugin's id, so an agent sees com_mattermost_plugin-tactical-fusion__decorate_text for the tool listed below as decorate_text.

ToolGive itGet back
decorate_text message, and optionally reference_time The text with every recognized token linked, whether anything changed, and whether the result fits a post
link_token type and token, and optionally label and reference_time One link, as markdown and as a URL
convert_coordinate format and value Every other reading of the coordinate, plus its country and its decimal latitude and longitude
lookup_airfield ident, an ICAO code The airfield's name, type, place, elevation and IATA code, and its position

These are the same operations the rest of this page documents, answered by the same code, so everything under Rules worth knowing applies to them too: the admin format switches still govern link_token, a link already written keeps working after a format is switched off, and lookup_airfield keeps resolving regardless. Refusals carry their own codes.

Only the Agents plugin may call this.

The /mcp endpoint answers only a request carrying the Agents plugin's own id, a header Mattermost sets itself and strips from anything a browser sends. It is not a general-purpose MCP server: there is no way to point an external MCP client at it directly, and a curl from a terminal is answered 403.

Rules worth knowing

  • Admin switches apply. A format an administrator turned off in the admin settings is not linked for another plugin either. link declines with reason disabled; decorate leaves the token as text. UTM ships off.
  • Embed the markdown as markdown. Do not HTML-escape it or wrap it in code, or it renders as text.
  • Do not add a host. URLs are root-relative so they follow whichever address the reader uses, and they already carry the server's subpath.
  • Posting the result is safe. Tactical Fusion's own message hook leaves existing decorator links alone, so nothing is linked twice.
  • Links keep working after a format is switched off, and stop working if Tactical Fusion is uninstalled, like every link it writes.
  • There is no per-user data on the bridge. Every answer depends only on the request and the admin settings, which is why a plugin needs no user to call it.

Versioning

This page describes bridge version 1, served at /bridge/v1 and reported as api_version and apiVersion. Within a version changes are additive only: new optional request fields, new response fields, new decorator types and new reasons. Treat a reason you do not recognize as "not linked". A breaking change would be a new path served alongside this one.

Errors

Every refusal is JSON with message, which ends in its code, code and, for a declined link, reason. The codes are TF-19000 to TF-19008, each explained under Plugin bridge on the Error Codes page.
