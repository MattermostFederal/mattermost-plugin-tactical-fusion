Admin Settings

System Console, Plugins, Tactical Fusion. Nine sections and forty switches. Thirty-eight are on by default; EnableLocationUTM and EnableGeoJSONUnlabeled are the two that are not.

How the date-time group switches relate

EnableDTG is the parent. The three below it select individual formats and only apply while the parent is on. The System Console groups them under a Date and time heading, but a section only arranges switches on a page: the parent is enforced in the plugin's own code, so turning it off stops every format below it whatever those are set to.

SettingGovernsDefault
EnableDTGDate-time group decoration as a wholeOn
EnableDTGMilitary091630ZAUG26 and the short formOn
EnableDTGMonikerThe DTG: labelOn
EnableDTGTimestampRFC 3339 timestampsOn

What a switch does and does not do

A switch governs new decoration only.

Links already written into existing messages keep working after their format is switched off. Turning one off stops new messages being decorated with it, and that is all. The decorator stays registered even with everything off, precisely so that the history keeps rendering.

Changes take effect immediately. The configuration is read fresh for every message, so no restart is needed.

The format switches also govern links that other plugins ask Tactical Fusion for. A format switched off here is not linked in a bot post or a component another plugin builds either; that plugin is told the format is disabled and shows the plain value. See Plugin Integration.

There is no "decorate at all" switch

With one decorator it would only duplicate EnableDTG. A second decorator should bring its own switch rather than reviving a global one.

Disabling the plugin is not a substitute for switching a format off.

Disabling the plugin also stops the route that serves the decorator pages, so every link already written into a message returns a 404. EnableDTG stops new decoration and leaves the history working. That is almost always what you actually want.

The map has its own section

Opening a coordinate draws a small world map, in the sidebar, on the hover card, under a coordinate-only post and on the standalone pages. The Maps section governs all of it: one parent and one switch per surface, so an install can drop the map entirely or keep it in some places and not others.

Off means nothing is fetched, not merely nothing is shown. With EnableLocationMap off, a reader's browser never asks for the basemap archive, the fonts on it or the library that draws it. That is the largest transfer this plugin makes, which is the main reason to turn it off.

Readers can still hide it for themselves, by unticking Map or Map under the post under Customize your view. The two are independent: your switch decides what is available, theirs decides what they look at. A surface you have turned off is not offered to them at all, and turning it back on returns each reader to whatever they had chosen. There is no way to force a map on for somebody who has hidden it.

The map reaches nothing outside your server.

The basemap, the fonts on it and the library that draws it all ship inside the plugin bundle and are served by your own Mattermost, at /plugins/com.mattermost.plugin-tactical-fusion/public/map/. There is no tile service, no map API and no key to configure, and an air-gapped install needs nothing added. The one consequence worth knowing is size: the basemap is the largest thing in the bundle by a wide margin, so a server with a tightened upload limit may refuse the plugin archive before it refuses anything else.

The country the map names in its accessible label is worked out the same way, from outlines compiled into the plugin. It is a basemap lookup and not an authority on borders, which is worth reading before anyone treats it as one.

The settings

Decorate date-time groups EnableDTG

TypeBoolean
DefaultOn

TypeBoolean
DefaultOn

Full details of what these forms accept are on the Date-Time Groups page.

Format: labeled date-time group EnableDTGMoniker

TypeBoolean
DefaultOn
MatchesA time introduced by the DTG: label, dropping the label from the link
RequiresEnableDTG, plus the format being labeled

This one composes: it only labels formats that are themselves on. Turning military formats off therefore also stops DTG: 091630ZAUG26, and a label with nothing left to label is dropped entirely. See the Date-Time Groups page.

Format: RFC 3339 timestamp EnableDTGTimestamp

TypeBoolean
DefaultOn
Matches2026-08-09T16:30:00Z and 2026-08-09T20:30:00+04:00
RequiresEnableDTG

Worth knowing before leaving this on in a channel that receives machine output: RFC 3339 timestamps are common in pasted logs, and a log excerpt outside a code fence will have every timestamp in it linked. Pasting logs inside a fence avoids this, since fenced code is never rewritten.

How the coordinate switches relate

EnableLocation is the parent, and the six below it select individual grammars and the moniker. The structure is the same as the date-time group block above, and so is the caveat: the Coordinates heading groups them on the page, and the parent is what actually gates them.

EnableLocation reaches further than its own section. Every switch under Maps is gated on it as well, because a map is only ever drawn for a coordinate this plugin decorated.

SettingGovernsDefault
EnableLocationCoordinate decoration as a wholeOn
EnableLocationDDSigned21.3353, -157.9483On
EnableLocationLatLonHemisphere-bearing latitude and longitudeOn
EnableLocationUSMTFThe fixed-width USMTF shapesOn
EnableLocationMGRSMilitary grid references (MGRS)On
EnableLocationUTMUTM, whose band letter is ambiguousOff
EnableLocationGEOREFGEOREF, behind its label onlyOn
EnableLocationGARSGARS, behind its label onlyOn

Every position is WGS 84. A coordinate carrying another datum is left alone rather than reinterpreted, because NAD 27 and WGS 84 disagree by up to about 200 m in the continental United States and quietly treating one as the other would move a grid reference by several cells.

Decorate coordinates EnableLocation

TypeBoolean
DefaultOn
Effect when offNo new message has a coordinate decorated, whatever the six switches below it say. Links already in existing messages keep working.

Recognize geographic coordinates in messages and rewrite them as links that open a Location panel.

Format: decimal degrees, signed EnableLocationDDSigned

TypeBoolean
DefaultOn
Matches21.3353, -157.9483
RequiresEnableLocation

Turn this one off first if ordinary numbers in your channels are being linked. It is the widest-reaching grammar here, because a signed decimal pair is two numbers and a comma with nothing else to identify it.

What holds it apart from ordinary text is a requirement of at least four decimal places on both values, which is about 11 m and is what real coordinate sources emit. The cost is that 21.34, -157.95 is deliberately left alone. See the declined list.

Format: latitude and longitude with hemisphere letters EnableLocationLatLon

TypeBoolean
DefaultOn
Matches21.3353 N, 157.9483 W, 21°20'07"N 157°56'53"W, 21°20.118'N 157°56.898'W
RequiresEnableLocation

Hemisphere letters are required in every variant, and a decimal point is required on the plain decimal form. Without that rule Load 12 N, 5 W would be read as a position rather than as newtons and watts.

Format: USMTF compact coordinates EnableLocationUSMTF

TypeBoolean
DefaultOn
Matches2120N15757W, 212007N1575654W, 212007.1N1575653.9W, 2120N9-15757W7
RequiresEnableLocation

The fixed-width shapes used in ATO and USMTF traffic. The shortest of them, 21N157W, is matched only behind a field label: seven characters resolving to a 111 km square is not something to detect on its own.

Format: military grid reference (MGRS) EnableLocationMGRS

TypeBoolean
DefaultOn
Matches4Q FJ 09060 59620, 4QFJ0906059620, 55P BR 76 02
RequiresEnableLocation

Grid references, which along with UTM are the only formats whose position is calculated rather than read out of the text the author typed. Everything else in this plugin is arithmetic on digits that are in the message; these two are a projection onto the WGS 84 ellipsoid. Turning both off leaves the plugin showing only what a message literally says.

A run-together grid reference is matched on its own when it is upper case and carries at least three digits per axis, which is a 100 m square. Lower case is not, because a short git commit hash is lower-case hexadecimal of exactly that shape; nor is a coarser one, because a shorter run is what part numbers look like (26HMA1997 is a valid grid reference). Both are still reached by spacing the reference out or by an MGRS: label.

A grid reference is validated against the letter scheme of the zone it names, so a square that does not exist is left alone: only eight of the twenty-four column letters are legal in any given zone. That check is also why MGRS has none of UTM's ambiguity: its band letter is followed by two more letters and could never be read as a hemisphere.

Above 84° north and below 80° south there is no grid: that is the Universal Polar Stereographic system, which this plugin does not implement. A polar coordinate is still decorated and still shows latitude and longitude; it simply has no grid rows.

Format: UTM EnableLocationUTM

TypeBoolean
DefaultOff, and the only format that ships disabled
Matches4Q 609060 2359620, 55P 276020E 1502660N, and run together only behind a UTMO: or UTMT: label
RequiresEnableLocation

This is the only format whose failure mode is a wrong position.

Every other switch on this page trades a false positive against a missed decoration: the worst case is that something which was not a coordinate gets linked, or something which was does not. UTM can decorate a real coordinate and point at the wrong place. That is why it ships off, and why turning it on is a decision worth making deliberately.

The letter after the zone number is read as a latitude band. 55P 276020E 1502660N is band S, so it resolves to 34° north. Somebody using the civilian convention writes the same characters to mean "zone 11, southern hemisphere", which is 56° south. The same text, two readings, 90° of latitude apart, and nothing in the token says which was meant.

The band reading is the one this plugin takes, because MGRS is the military implementation of UTM and the third character of a grid zone designator is a latitude band. What limits the damage is that the northing has to land inside the band its letter names: 11N 385000 3769000 is declined, because that northing is 34° north, which is band S. Measured over 20,000 generated positions written the civilian way, about nine in ten are declined by that check. Not all of them.

The two letters do not carry the same risk. For N, both readings put the point in the same place and the band reading merely also requires it to be in the first 8° north, so it can decline a coordinate but never move one. S is where the difference is real.

When to turn it on

Turn it on if your workspace writes UTM the military way, which is the common case anywhere MGRS is in use: the reading will be the one your people meant. Leave it off if UTM reaches your channels from civilian tooling, GPS exports or mapping software, where 11S is likely to mean the southern hemisphere.

Leaving it off costs nothing else. A UTM position is still shown as a row in the panel for every other coordinate that is decorated; this switch governs only whether a UTM token in a message becomes a link. Authors who want one linked can write it as a grid reference instead, where the band letter cannot be misread.

Run-together UTM is label-only whatever this is set to: after the zone and band it is thirteen bare digits with no letters to validate, so the only check available is the band containment above, which a great many thirteen-digit runs satisfy.

Format: GEOREF EnableLocationGEOREF

TypeBoolean
DefaultOn
MatchesGEOREF:XGKP5535, GEOREF:XGKP553350 and GEOREF:XGKP55803503, behind the label only
RequiresEnableLocation and EnableLocationMoniker

The World Geographic Reference System divides the globe into 15° zones and bands, then degrees, then minutes. A code names a cell rather than a point, so the position shown for one is its center, and the three digit widths are whole minutes, tenths and hundredths.

GEOREF is written longitude first, which is the opposite of every other format here and is the standard's own order. In XGKP5535 the X and the K are longitude and the 55 is its minutes; G, P and 35 are latitude.

This format is matched behind its label and never bare. Four letters and four digits has nothing in it that a part number does not, so a bare pattern would rewrite ordinary text. That is the same posture LATD is held to, for the same reason. Turning EnableLocationMoniker off therefore removes this format entirely.

Turning this switch off costs no GEOREF row. Every decorated coordinate still shows one, because that is derived from the position rather than matched in the text.

Format: GARS EnableLocationGARS

TypeBoolean
DefaultOn
MatchesGARS:045KG, GARS:045KG1 and GARS:045KG14, behind the label only
RequiresEnableLocation and EnableLocationMoniker

The Global Area Reference System divides the globe into 30-minute cells, named by three digits of longitude and two letters of latitude, then optionally a 15-minute quadrant and a 5-minute cell inside that. As with GEOREF, a code names a cell and the position shown for one is its center.

Label only, and this is the stronger case of the two. 045KG14 is seven alphanumerics whose only structural check is that just over a third of the possible letter pairs name no band at all. There is nothing else in it to tell a coordinate from a part number.

Format: Plus Code EnableLocationPlusCode

TypeBoolean
DefaultOn
Matches73H483P2+4M, 73H483P2+4MG and the padded 73H40000+. Bare in upper case; lower case behind a PLUSCODE: or OLC: label
RequiresEnableLocation. The labeled lower-case form also needs EnableLocationMoniker; the bare upper-case form does not

An Open Location Code, which is what Google Maps calls a Plus Code. It is the one format added alongside GEOREF and GARS that is matched without a label, because its twenty-character alphabet contains no vowel at all, so an eight-character run of it is not a word, and its separator sits at a fixed position in the middle.

Unlabeled it is upper case only, and that restriction was measured rather than assumed. A lower-case run of that shape is what a version string with build metadata looks like, and roughly one in 50,000 of those is a well-formed code. Lower case is still matched behind the label, and Plus Codes are canonically written in upper case anyway.

Short codes are left alone. CWC8+R9 is meaningless without a nearby reference location, which this plugin does not have and would have to guess at. Only full codes are matched.

Turn this off if your channels carry identifiers shaped like ABCDEFGH+IJ. As with every other format here, the Plus Code row stays either way.

Format: labeled coordinate EnableLocationMoniker

TypeBoolean
DefaultOn
MatchesA coordinate introduced by a field label such as LATM:, LATS:, DMPID:, GEOK:, MGRS:, USNG:, UTMO:, UTMT:, GEOREF:, GARS: or PLUSCODE:
RequiresEnableLocation, plus the format being labeled

USNG: labels a grid reference. The United States National Grid is MGRS on WGS 84, character for character, so there is no separate format for it: a USNG: token is read, stored and rendered as MGRS.

Three formats are reachable only through this switch: LATD, GEOREF and GARS. Turning it off removes them entirely rather than narrowing them.

Like the DTG: label, a coordinate label is consumed: the label and the token together become the link. This one composes the same way the date-time group label does: it only labels formats that are themselves on, and a label vouches for nothing, so LATM:9999N99999W stays declined.

How the map switches relate

EnableLocationMap is the parent of the Maps section, and the three below it select individual surfaces. Unlike the two sections above, this one has a parent outside itself as well: EnableLocation gates every switch here, because a map is only ever drawn for a coordinate this plugin decorated.

SettingGovernsDefault
EnableLocationMapMaps as a whole, on every surfaceOn
EnableLocationMapPanelThe sidebar panel and the hover cardOn
EnableLocationMapInlineThe map under a coordinate-only postOn
EnableLocationMapPageThe full-window map pageOn
LocationMapPackagesDirWhere detail map packages are read fromEmpty
LocationMapPackagesInstall or remove one detail areaNot a stored value

These are the only switches in this plugin that are read at render rather than only when a message is posted. A format switch governs text that is already written permanently into a message, so turning one off cannot change what a link already out there does. A map is drawn afresh each time somebody looks, so turning one off reaches every coordinate, including the ones posted last year, rather than only the ones posted next. A client that is already open can lag the change by up to half an hour, which is how long it keeps its copy of these settings; a reload applies it at once.

Draw maps for coordinates EnableLocationMap

TypeBoolean
DefaultOn
Effect when offNo map is drawn anywhere, whatever the three switches below it say, and no client requests the basemap archive, its fonts or the map library. Every reading still renders.
RequiresEnableLocation

The basemap ships inside the plugin and is served by your own Mattermost, so turning this off is about weight rather than about reaching outside: it is the largest transfer this plugin makes, and on a constrained or metered link that is the reason to drop it.

The file still ships either way.

Mattermost serves the plugin's public/ directory itself, before the plugin sees the request, so this switch stops clients asking for the basemap rather than making it unreachable. The bundle is the same size on disk whichever way it is set, and anyone with a session can still fetch the archive by its address.

Map in the sidebar and hover card EnableLocationMapPanel

TypeBoolean
DefaultOn
Effect when offEvery table of readings opens with no map above it, in the sidebar and on the coordinate's standalone page alike, and pointing at a coordinate link shows no card at all.
RequiresEnableLocation and EnableLocationMap

The hover card goes with the panel map rather than having a switch of its own, because that card is the map and nothing else. With no picture in it there is nothing left to show, so the card is suppressed instead of appearing empty. Clicking still opens the sidebar.

It reaches further than its name suggests. What it governs is the map drawn above a table of readings, wherever that table appears, and that includes the coordinate's own standalone page as well as the sidebar. The setting below governs the separate full-window map page, which is a different surface.

Map under a post EnableLocationMapInline

This switch governs every map this plugin draws in the channel itself: the one under a coordinate-only post, and the one on a Cursor on Target card. It does not affect the sidebar, the hover card or the map page.

TypeBoolean
DefaultOn
Effect when offA message whose whole text is one coordinate stays an ordinary post: the link is decorated as usual and no map is drawn beneath it. A Cursor on Target card is still rendered, without its map.
RequiresEnableLocation and EnableLocationMap

This is the one switch in the section that changes the stored post rather than only what is drawn. To render a map under a message, the plugin marks that post with a custom type as it is created, and a marked post carries real costs.

Marked posts are missing from Elasticsearch and OpenSearch results.

Those engines match on an allow list of ordinary and attachment posts, so a marked post is indexed and then never matched: it will not appear in search, nor in Recent Mentions. Link previews, image embeds and automatic translation are dropped for it too. Installs that search through Postgres are unaffected. Turning this off leaves those messages ordinary and gets all of it back.

It applies from the moment you change it, but only to new messages. A post already marked keeps its mark, because the mark survives editing and this plugin deliberately never rewrites a message somebody has edited. Such a post renders as the plain decorated link with no map, and stays outside Elasticsearch results. There is no way to unmark one short of deleting and reposting it.

Full-window map page EnableLocationMapPage

TypeBoolean
DefaultOn
Effect when offThe map page answers "not found" and the Open larger link is not drawn. The coordinate's own page, with every reading on it, is unaffected.
RequiresEnableLocation and EnableLocationMap

This is the page that gives the whole window to one picture, which Open larger opens and which a client that does not run the webapp follows a coordinate link to. It is addressed two ways: by a coordinate, and by a post, which is how a Cursor on Target block and a GeoJSON document open, since neither has a coordinate that names it. Opening one by post re-reads the post and checks the reader may see its channel. It is the only route an admin switch removes outright, and that is deliberate: the page is the map, so there is no reduced version of it worth serving, where the readings page still has everything but the picture.

Detail map package directory LocationMapPackagesDir

TypeText, a directory path on this server
DefaultEmpty, meaning bundled packages only
Effect when emptyOnly the detail packages the plugin ships are drawn. Everything else is unchanged.
RequiresEnableLocation and EnableLocationMap

Above zoom 10 the map draws OpenStreetMap rather than Natural Earth, for the areas this install has. Each area is one file, named <command>-<area>.pmtiles, such as indopacom-hawaii.pmtiles. Point this setting at a directory, drop a file in it, and the area appears; there is no restart and no upload step. A file here replaces a bundled package of the same name, which is how an area gets a newer build without waiting for a plugin release.

Where the files come from. This plugin ships with Hawaii and Guam built in. Every other area is a separate download attached to the plugin's GitHub release, alongside the plugin bundle itself, with a PACKAGES.sha256 beside them you can verify against. Download only the areas you need: they range from a couple of megabytes to a few hundred, which is exactly why they are not in the bundle. Areas currently published cover Korea, Taiwan, Japan, the Philippines, the South China Sea, Guam, the Persian Gulf, the Levant, the Red Sea, Ukraine, the Baltics and the Horn of Africa.

Names are checked rather than cleaned: lower case, letters and digits, and at least one hyphen. Anything else in the directory is ignored, and so is any file that is not a valid map archive built for zoom 10 and up. Both are logged with a code, because a package that is quietly skipped looks exactly like an area nobody built.

An area outlives a plugin upgrade, but not every one of them. Each archive is stamped with the map schema it was built for, so a build that has moved on can say which of the two is behind rather than reporting a well formed file as a broken one. The refusal names the direction: an older archive asks you to re-download the area, and a newer one means the plugin is behind the archive and should be upgraded. This only happens when the shape of the map data changed, not when an area is merely shallower than another, so upgrading the plugin does not normally mean moving gigabytes again. See a detail area that will not install.

Every node in a cluster needs this directory.

Each node serves the archives it can read, so a package present on one node alone is drawn for the readers that node happens to serve and not for anybody else, with nothing on screen explaining the difference. Use shared storage, or put an identical copy on every node.

Installed detail areas LocationMapPackages

TypeA control, not a stored value
DefaultWhatever is in the package directory
RequiresLocationMapPackagesDir

Lists the detail areas this node has and lets you install or remove one without reaching the filesystem. It writes into the package directory above, which is the same place a file copied there by hand is read from: a map archive is served by byte range, so it has to sit on disk, and there is no plugin storage that can serve a range. Upload and copy are two doors into one room.

The area's name comes from the file rather than a field, so name the file for the area it holds. An upload is checked before it is put in place, so a truncated or wrongly built archive is refused with a reason instead of being accepted and then quietly skipped.

Remove is offered only where Remove can work. An area that ships inside the plugin is listed with ships with the plugin in place of a button, because a release is what replaces it and there is no file here to unlink. Removing a dropped-in area that shadowed a bundled one of the same name succeeds and leaves the name listed, since the bundled copy underneath resurfaces, and the row loses its button at the same moment. Every refusal this control can show is quoted in troubleshooting.

Large areas should be copied, not uploaded.

An upload crosses this server's own request limits and whatever proxy sits in front of it, which a large area will exceed. Copying the file into the package directory has no such ceiling. In a cluster an upload also reaches only the node that served it, where a copy can be placed on shared storage.

The airfield switches

Decorate airfield codes EnableAirport

TypeBoolean
DefaultOn
Effect when offNew messages stop having airfield codes linked. Links already written keep working, and the airfield panel and page keep answering.
RequiresNothing

Recognizes an ICAO airfield code written behind one of the four USMTF field labels that introduce one: ICAO:, LOC:, DEPLOC: and ARRLOC:. The panel names the airfield, where it is, its elevation, its IATA code, its runways and its frequencies, and draws its position and runways from the built-in database.

There is one switch rather than a family of them, unlike coordinates. A code is only ever recognized behind a label, so there is no second grammar to turn off separately, and a "labels only" switch would just be this one under another name.

The label is required, and it must be upper case. That is not strictness for its own sake. An airfield code is four letters, which is what ordinary words are made of: 349 of the codes in the database are English dictionary words, including FACT (Cape Town International) and FAST (Somerset East). USCG is an airfield in Russia and LIMA is one in Italy. Matching four bare letters would rewrite ordinary sentences into links pointing at the wrong side of the world, and matching a lower-case label would do the same to a line like loc: fast turnaround on the ramp.

The airfield's position comes from a database compiled into the plugin, so nothing is fetched and this works on an air-gapped install. The panel names its source beside the airfield, because the position is a lookup rather than something computed from what the author typed. Refreshing that database is a plugin upgrade.

Decorating only what an author labeled

Leaving EnableLocationUSMTF and EnableLocationMoniker on while turning the other two off is a supported configuration, and a deliberate one. It decorates a coordinate only where the author wrote a field label in front of it, which removes bare detection entirely.

Consider it for a workspace where messages carry a lot of numeric data and a false positive would be worse than a missed link.

Checking the current behavior

Decorate IATA codes behind their label EnableAirportIATA

TypeBoolean
DefaultOn
Effect when offNew messages stop having IATA: codes linked. Links already written keep working, and the panel and page keep resolving them.
RequiresEnableAirport

Recognizes a three-letter IATA airport code written behind IATA:, in upper case, such as IATA:HNL. It opens the same Airfield panel the ICAO code does. Three letters collide with ordinary words even more often than four do, so the label is required and a bare code is never read; there is no switch that produces one.

Show the airfield details under a labeled code on its own EnableAirportTable

TypeBoolean
DefaultOn
Effect when offNew messages that are nothing but an airfield code get the link alone. Messages already posted keep the table they were given.
RequiresEnableAirport

When a message contains nothing but one labeled airfield reference, such as ICAO:PHNL or a set line ending DEPLOC:PHNL//, it is replaced with a small table of the field's details: its name, the code the author typed, where it is, what kind of field it is, its elevation and its IATA code. The name and the last row both open the panel, which is where the map and the coordinate readings are. The code the author typed stays in the table, so searching for it still finds the message.

The table is written into the message itself.

It is ordinary markdown in the stored message, not something drawn on top of it. That is deliberate, and it is what makes the message render the same way everywhere, including on mobile and in any client that does not run this plugin's web code, and what keeps the post searchable and exportable like any other.

It also means the table is permanent and fixed. An author who edits the post sees the markdown and can change or delete it. The values are those the database held when the message was posted: if a later version of the plugin corrects an elevation, messages already posted keep the old one. Turning this setting off stops new messages being expanded and does not remove the tables already written.

/tactical-fusion examples runs the real matcher against a set of samples and posts what it did, including a note when decoration is switched off entirely. That is the quickest way to confirm a settings change took effect.

/tactical-fusion check answers the same question about one specific message, which is what to reach for when somebody reports that a coordinate was not linked.

Draw a map under a message of nothing but airfield codes EnableAirportRoute

TypeBoolean
DefaultOn
Effect when offNew messages of nothing but airfield codes are decorated and get no map. Posts already stamped keep their map.
RequiresEnableAirport, EnableLocationMapInline and its parents

When a message is nothing but labeled airfield references, such as DEPLOC:PHIK ARRLOC:PGUA//, every airfield is drawn on one map under the post, numbered in message order with a leg between each pair, and the links stay in the message. A message of one code gets the table instead while that is on.

This sets the post's type.

A post with a custom type is excluded from Elasticsearch and OpenSearch results and from Recent Mentions, is not auto-translated, and loses its link previews. The map under a lone coordinate and the Cursor on Target card pay the same cost, and this switch is how an install declines it for routes.

The Cursor on Target switches

Render Cursor on Target events EnableCot

TypeBoolean
DefaultOn
Effect when offA pasted event stays an ordinary fenced code block. Posts already rendered keep their card.
RequiresNothing

A Cursor on Target event written in a cot or xml fenced block is read as it is posted, and the post is rendered as a card: the callsign and decoded type, the position, the timing, and how accurately the position is known. Text written around the block is kept and shown with the card.

Rendered posts are missing from Elasticsearch and OpenSearch results.

To render a card the plugin marks the post with a custom type as it is created. Elasticsearch and OpenSearch match only ordinary posts, so a marked post is indexed and then never found, and it is absent from Recent Mentions as well. Installs that search through PostgreSQL are unaffected.

Marking also drops link previews, image embeds and automatic translation for that post, and any Markdown written around the event renders as plain text. Turning this switch off restores all of it for new posts.

Read a Cursor on Target file attached to a post EnableCotFile

TypeBoolean
DefaultOn
Effect when offAn attached .xml or .cot file is left as an ordinary attachment. A pasted fenced block still renders.
RequiresEnableCot

When a post carries exactly one attachment whose name ends .xml or .cot, the file is read as the post is created and the event inside it is rendered. This and EnableGeoJSONFile are the two settings that read a file while a message is being posted. An install whose file storage is slow or remote may prefer to turn it off and keep the fenced block, which costs nothing extra. Files over 64 KB are ignored either way.

GeoJSON

Render GeoJSON documents EnableGeoJSON

TypeBoolean
DefaultOn
Effect when offA pasted document is left as an ordinary code block. Posts already rendered keep their card.

A GeoJSON document written in a fenced code block labeled geojson is rendered as a card listing how many features the document holds and of what geometry, naming each one, showing the properties it carries, and drawing them all on one map.

A block labeled json is deliberately not recognized. Rendering a post this way marks it with a custom type, and Elasticsearch and OpenSearch index such a post but never match it, so it is missing from search and from Recent Mentions; link previews, image embeds and automatic translation are dropped as well. That is permanent and the author cannot undo it, and ordinary JSON is pasted into chat far too often to risk it. Installs searching through Postgres are unaffected either way.

Read a GeoJSON file attached to a post EnableGeoJSONFile

TypeBoolean
DefaultOn

RequiresEnableGeoJSON

When a post carries exactly one attachment whose name ends .geojson, the file is read as the post is created and the document inside it is rendered. Like the Cursor on Target file switch, this puts a filestore read on the post path, so an install whose file storage is slow or remote may prefer to turn it off. Files over 64 KB are ignored either way, and a .json attachment is read only when EnableGeoJSONUnlabeled is also on, which it is not by default.

Also read GeoJSON that does not say it is GeoJSON (off by default) EnableGeoJSONUnlabeled

TypeBoolean
DefaultOff
Effect when onA json fence, a .json attachment, and a document pasted with no fence at all are all read as GeoJSON.
RequiresEnableGeoJSON

One of two switches in the plugin that ships off, and the reason is the cost of being wrong. Rendering a post marks it with a custom type, which takes away its Elasticsearch and OpenSearch matches and its embeds permanently, and the author cannot undo it. Ordinary JSON is pasted into chat constantly, so a workspace that has not asked for this should not get it.

Turning it on suits an install whose channels carry overlays rather than API payloads. It widens what is read, never what is accepted: a document that does not parse as GeoJSON is still left alone, and a block the author fenced as code is never read. Only a block labeled geojson gets a message explaining a refusal; the ambiguous spellings fail silently, because a notice on every one of them would fire constantly on ordinary posts.

Cyber dataset directory CyberDatasetsDir

TypeText
DefaultEmpty
Example/opt/mattermost/tactical-fusion/cyber
Effect when emptyOnly the datasets the plugin ships are read. Indicators still decorate; the panel says which datasets are not installed.

A directory on this server holding the datasets the enrichment reads: cve.tsv, cvedetail.tsv, cwedetail.tsv, attackdetail.tsv, advisory.tsv, threat.tsv, malware.tsv, epss.tsv, kev.tsv, ip.tsv and watchlist.tsv, plus any vendor .mmdb database. Drop a file in and it is read within a few seconds without restarting anything; a file here replaces a bundled one of the same name. Leave this empty to use only the datasets the plugin ships.

A dataset may be dropped in gzipped, as cve.tsv.gz, which is how the release publishes them. The plugin unpacks it beside itself into cve.tsv, so the directory must be writable by the Mattermost server; on read-only media, unpack it yourself with gunzip -k. See where the data comes from.

In a cluster every node must see this directory.

Each node answers from the files it can read, so a dataset present on one node alone enriches for some readers and not others. See Troubleshooting for what that looks like from a reader's side.

Loaded datasets CyberDatasetsLoaded

TypeA report, not a stored value
DefaultWhatever this node has loaded

Shows what this node has read from the bundle and from the dataset directory: each dataset's file, whether it came with the plugin or from the directory, how many records it holds, its size, and the date its stamp says it was generated. Below that come each vendor .mmdb database with its type and build date, the datasets that are not installed, any bundled file a file in the directory replaces, and every file that was skipped, with the reason and its error code.

Datasets are searched on disk rather than loaded, so a record count means reading the file once. That happens the first time the list is opened after a dataset changes, and can take a moment on the full vulnerability set; after that the count is kept until the file changes. In a cluster the list is the node that answered, which is how to find a node missing a file the others have.

Reader settings are not admin settings

Timezone rows and the countdown flash threshold are chosen by each reader and stored per user. There is no server-wide default for them beyond the built-in one, and an admin cannot set them on somebody's behalf.
