Date and Time Formats

What gets linked, what does not, and why the "does not" list is as long as it is.

Every format below can be switched off individually in the System Console. See Admin Settings. To see the current behaviour of your own server rather than this page, run /tactical-fusion examples, which runs the real matcher and posts what it did.

The rule everything follows

A format is eligible only if it resolves to a single instant. The link bakes an instant into its query string and the panel counts down to it, so anything needing a timezone invented for it is out. That single rule explains most of the declined list.

Military date-time group

Setting: EnableDTGMilitary

FormExampleNotes
DDHHMM + zone + MMM + YY 091630ZAUG26 Any zone letter except I and J. Month abbreviation is case insensitive.
DDHHMM + zone + MMM + YYYY 091630ZAUG2026 Same, with a four digit year.
DDHHMM + Z 091630Z Short form. Literal Z only. Month and year are taken from the date the message was posted, and the panel says so.

The year is restricted to 2000 to 2099, which is exactly the range two year digits can name without ambiguity.

091630R is not a date-time group here. The short form accepts only Z, because a bare six digits followed by a single letter is far too easy to hit by accident. Write 091630RAUG26 if you mean Romeo.

Labelled date-time group

Setting: EnableDTGMoniker

Some military formats mark where a time starts with a DTG: label. The label is matched and then dropped, so only the token itself becomes the link text:

You typeThe link text is
DTG: 091630ZAUG26091630ZAUG26
dtg:091630ZAUG26091630ZAUG26
DTG : 091630ZAUG26091630ZAUG26

Spacing either side of the colon is optional and the label is case insensitive. The token keeps its own casing rules.

The label vouches for nothing.

A token it marks still has to be a real one. DTG: 091630R is declined exactly as 091630R is. The label also only applies to formats that are themselves switched on, so turning military formats off also stops DTG: 091630ZAUG26.

RFC 3339 timestamp

Setting: EnableDTGTimestamp

The extended form only, with the hyphens and colons present:

ExampleNotes
2026-08-09T16:30:00ZUTC.
2026-08-09T20:30:00+04:00Any offset, including half and quarter hour ones.
2026-08-09T16:30ZSeconds are optional.
2026-08-09T16:30:00.250ZFractional seconds are parsed and then discarded.
2026-08-09t16:30:00zLowercase t and z are accepted.

Military groups and RFC 3339 timestamps share one decorator because once parsed they are the same thing: an instant, plus the offset it was written in. They differ only in how that offset is carried, since an offset of +05:45 has no military letter to name it.

Deliberately declined

These look like times and are not matched. Each one is absent for a reason, and the reason is usually that a false positive here would corrupt somebody's message, since decoration rewrites what they wrote.

Not matchedExampleWhy
Epoch seconds 1786293000 Any ten digit number would qualify. Order numbers, ticket ids and phone numbers would all become links.
12 hour clocks 4:30 PM No date and no zone, so it names no instant. It would also match inside ordinary prose constantly.
Named zone abbreviations 16:30 CST CST is three different zones. EST collides with the abbreviation for "estimated".
Basic ISO 8601 20260809T163000Z With no hyphens there is no word boundary, so it would match inside snapshot-20260809T163000Z.zip.
Bare dates 2026-08-09 Names a day, not an instant. Which midnight, in which zone?
Zoneless times 2026-08-09T16:30 Same problem. A zone would have to be invented for it.

Spans that are never rewritten

The matcher protects spans, not whole messages. A token in ordinary prose is still linked even when the message also contains a code block or a URL; a token inside one of those is left alone. So this: 

[the plan](https://example.com/brief) says 091630ZAUG26

links the date-time group and leaves the existing link untouched.

The protected constructs are:

  • Fenced code blocks, including unterminated ones and ~~~ fences
  • Indented code blocks
  • Inline code of any backtick width
  • Links, images, and reference definitions
  • Any bracketed span
  • Angle autolinks, such as <https://example.com>
  • Inline HTML tags
  • Bare URLs beginning scheme:// or www.

Decoration is also skipped entirely, leaving the message exactly as written, when the result would exceed the maximum post size. A twelve character date-time group becomes roughly a hundred and twenty once linked, so a message that visibly fits can cross the limit here. Posting it undecorated is better than showing the author an opaque "too long" error for text they can see fits.
