The Sidebar Panel

Reading a date-time group, and making the table your own.

Hovering a link

Point at a decorated time and a small card appears showing the countdown only: how long until that instant, or how long since. That is deliberately all it shows. The reading and the timezone table are worth opening the sidebar for; a countdown is worth a glance.

Clicking a link

Clicking opens the right-hand sidebar. The browser does not navigate, so you do not lose your place in the channel. The panel has four parts:

Countdown Time remaining until the instant, counting down live. It flashes once the instant is close, which by default means within 30 minutes.
Reading The instant written out in full, in the offset it was originally written in: 09 Aug 2026 16:30 Z. Seconds appear only when there are seconds to show, so 2026-08-09T16:30:45Z reads 09 Aug 2026 16:30:45 Z while 2026-08-09T16:30:00Z stays 16:30: a written :00 has nothing to lose, and padding it on would claim a field the row does not need. A date-time group has no seconds field, so it never shows one.
Canonical form The token as the parser understood it, in monospace. Useful for confirming that a short form was read the way you meant.
Timezone table The same instant in each of your timezones, ordered west to east. Times follow the reading: to the minute, and to the second when the original text was written that finely.

The date column badges

A +1 or -1 next to a date means that row falls on a different calendar day from the token itself. The comparison is against the token's own zone, not UTC, so a group written in +04:00 does not badge half the table as a day out.

Short forms say what they assumed

A short form such as 091630Z carries no month and no year, so both are taken from the date the message was posted. The panel states this in italics beneath the reading rather than presenting an inferred date as fact.

The standalone page

Clients that do not run the plugin's web bundle, notably the mobile app, get a page of their own instead of the sidebar. It shows the same countdown and the same table, because for a coordinate it runs the same code the sidebar does: the server validates the link and works out every reading, and the page draws them.

It requires a Mattermost login. Opening one of these links without a session takes you to the sign-in page first and then on to the coordinate you clicked, so a session that expired while you were reading costs you a sign-in rather than the link. The map page behind Open larger works the same way.

The standalone page always shows the built-in defaults.

The page does not ask who is reading it, even though it now requires a login: it is rendered from the link alone. If you have customised your view, the sidebar and the page will disagree about the same date-time group.

The location panel

Clicking a coordinate opens the same sidebar with a Location panel.

Most of it is worked out from the link alone and is on screen the instant the panel opens. The two grid rows are the exception: a grid reference is a projection onto an ellipsoid, that projection runs on the server, so those rows are fetched. See what happens when the request does not arrive, which is never a blank panel.

As writtenThe author's own text, exactly as they typed it. It opens the table, so every reading below it is visibly derived from the line above.
Lat / lonDecimal degrees with hemisphere letters.
DMSDegrees, minutes and seconds.
DDMDegrees and decimal minutes.
MGRSThe military grid reference, at the resolution the original text carried. It follows the three angular readings rather than opening the table, so the notations that read the same way sit together.
USMTFThe fixed-width compact form, for pasting into an ATO or a USMTF field. The shape follows the resolution: 35N079W for a degrees-only coordinate, 3510N07901W at whole minutes, 400948N1221400W at whole seconds, and 331000.0N1183000.0W finer than that. Sized from the pair rather than per axis, because it is one shape covering both halves. It never carries confidence digits: those say how well a position is known, which a derived reading cannot claim.
UTMZone, band, easting and northing, rounded to the same resolution.
ResolutionHow finely the original text was written, in meters. For a grid reference, how big the square is.
ConfidenceOnly for a verified USMTF coordinate, which states one.
DatumAlways WGS 84.
NormalizedThe canonical form, shown only when it differs from what the author typed.

The map

The panel draws a small world map above the table, centred on the coordinate, and Open larger beneath it opens a page that is nothing but the map. The standalone page the mobile app opens draws the same map above the same table. All three are the same map: drag to pan, scroll to zoom, the + and − buttons in the corner, the arrow and + / − keys once the map has focus, and Reset view to return to the opening centre and zoom.

The map page carries one line beneath the picture: the coordinate exactly as the author wrote it, and All readings, which opens the full table for the same coordinate. Both pages open in whichever theme, light or dark, you are using in Mattermost.

Everything the map needs is bundled with the plugin and served from your own Mattermost, so it works with no network at all: no tile service, no map API, nothing fetched from outside. This is the one part of the plugin designed first for disconnected and air-gapped installs rather than adapted to them.

The map is the first thing Customize your view offers to hide, and unticking it there is also how you get it back. Hiding it costs you the country as well, which has nowhere else to appear.

The standalone page needs JavaScript.

The sidebar, the standalone page and the map page all run the same code, which is what keeps them from disagreeing about a coordinate. The readings on the standalone page are worked out on the server and delivered with the page, so nothing waits on a second request, but the page draws nothing until its script has loaded.

The map needs WebGL2.

Drawing happens in the browser, which on a hardened or virtualised desktop with WebGL disabled means no map. The panel and the page both say so in place of the map, and every reading in the table still renders: the coordinate and the conversions are worked out on the server and do not depend on it. The country is the exception: it is named by the map itself, so no map means no country either.

The basemap is Natural Earth, drawn from vector tiles. It carries coastlines and lakes, country and province boundaries, major roads and railways, rivers, built-up areas, and the names of countries and towns. Detail follows how far in you are: the whole world is drawn at 1:110 million, and as you zoom the map moves to 1:50 million and then 1:10 million, so features sharpen rather than going blurry.

A coordinate opens on its region rather than its continent, framing roughly 400 kilometres across. Zoom out for orientation, or in as far as the map will go. Reset view returns to the opening frame.

It is still not a navigation chart. Even at its finest it is accurate to roughly five kilometres and it carries no streets, no buildings and no terrain. That accuracy is also why the map stops zooming where it does: past that point a coastline drawn five kilometres from where it really is starts to look like fact rather than generalisation. It answers which part of the world is this, and the square around the pin, not the coastline under it, is what states how precisely the original text located anything.

About the names on the map.

Every country Natural Earth lists is named, including disputed territories, because leaving one out would be a judgement this plugin does not make. Country names give way to town names as you zoom in, and which names appear at all is decided by the room available and by Natural Earth's own ranking, so zooming changes what is written on the map. Names are drawn in a bundled Latin typeface and taken from Natural Earth's English field, so a place whose local name is in another script is shown under its English name.

The square around the pin

A coordinate written to whole degrees is drawn with a large rectangle around it, and one written to a metre with a rectangle so small it reads as the dot alone until you zoom in. The rectangle is the area the original text actually names, so a coarse coordinate looks coarse. Without it 35N079W, which names a square about 111 km across, would be indistinguishable from a ten-figure grid reference that names a square one metre across.

It is drawn at the size of the square, not twice it, and each half of the coordinate uses its own resolution, so a position written finely in latitude and coarsely in longitude is drawn as the tall thin rectangle it is. Nothing is ever dropped for being small: a very fine coordinate simply draws a rectangle below a pixel, which becomes visible as you zoom toward it, because a threshold guessing on your behalf would answer a question you had not asked. The Resolution row carries the figure either way.

It is not a range ring.

The shape around the pin says how precisely the coordinate was written. It is not a weapons envelope, not a communications range, not a search radius and not a GPS accuracy estimate. It is drawn as a rectangle rather than a circle partly for that reason, and partly because a grid reference names a square.

Positions the map cannot show

The projection the map uses runs out at about 85 degrees north and south. A coordinate beyond that is a perfectly good position and every reading still renders, but the map is left out and a line says so rather than drawing a pin up to 550 km from where the coordinate actually is. Coordinates either side of the 180th meridian are drawn correctly, with land on both sides.

Naming the country

The country a position falls in is worked out on the server, by testing the point against bundled country outlines. Those outlines are a separate copy of the data from the one the map draws, kept at 1:110 million whatever the map is showing, which is why the value cites that scale even when you have zoomed past it. It is not a row in the table: the map speaks it in its accessible label and nowhere else. So it is there when the map is, and not when it is not.

This is a basemap lookup, not an authority on borders.

It cites its source in the value itself, as United States of America (Natural Earth 110m), because that is what it is: a point tested against a public-domain dataset whose borders are generalised by roughly a kilometre. Near any border, and anywhere a border is disputed, treat it as a hint about which part of the world you are looking at and nothing more. It is not a determination of sovereignty and must not be used as one.

Where the dataset gives more than one answer, the plugin does not choose between them. It names the administering entity rather than a claimed sovereign, and it is deliberately silent rather than approximate: a position in no country at all, such as open ocean, omits the row rather than naming the nearest land.

Resolution is not accuracy

The row says about 11 m, not accurate to 11 m. It describes how finely the text was written and nothing else. A phone with 5 m of real accuracy still emits six decimals, and a row headed "precision" would invite reading that as a claim about the fix.

Every other row is rendered at that same resolution. A coordinate written to two decimals shows 34.06° N, and one written to whole degrees shows 35°N rather than 35°00'00"N. Padding a field the author never wrote would be a claim they did not make.

When the two halves were written to different precision, each half keeps its own. 34.0561N,118.2W shows 34.0561° N, 118.2° W, and the resolution row reads about 11.1 km, which is what the coarser half is worth. The two are not in conflict: the resolution describes how well the pair is known, while each value shows every digit its author actually typed. Rendering the latitude at the longitude's single decimal would move it 4.9 km north, which is a loss of real information rather than a refusal to overstate.

Grid references name squares

32U MV 12 34 is a 1 km square, and the latitude and longitude shown for it are that square's center. The resolution row says so. Read as a corner instead, a 10 km reference would put a reader 7 km from where the grid points.

The grid rows follow the same resolution rule as everything else, which most conversion tools do not: a coordinate written to whole degrees gets a 100 km square, not a ten-figure reference implying it is known to the meter. The UTM row is the same numbers as the grid reference whenever the link is a grid one, because the digits of a grid reference are literally its south-west corner on the UTM grid.

Above 84° north and below 80° south there is no UTM grid, so both rows are simply absent. Everything else on the panel is unaffected.

When the conversion does not arrive

The grid rows are the only ones fetched, and losing them costs only them. The rest of the panel is computed from the link and is already on screen.

While waitingThe fetched rows read converting…
Request failedThey read unavailable. Nothing is blank and nothing shows a zero, because a row reading 0.0000° N, 0.0000° E because a conversion failed would be a position, and a wrong one.
Server refused the linkThe panel says Not a coordinate and shows nothing else.

That last case is a verdict rather than an outage, and the two are kept apart deliberately. A hand-edited link can pass the checks the browser is able to make and still not be one this plugin issued; only the server can tell, because the check needs the coordinate grammar. Rather than render a position that might name somewhere else entirely, the panel declines, exactly as the standalone page does for the same link. If you see this on a link you did not edit, it is worth reporting with code TF-13008.

As written, and normalized

The As written row opens the table and carries the author's own characters, including the symbols and spacing they used, so every reading under it is visibly derived from that one line. Normalized closes the table with the canonical form the link was validated against, and appears only when the two differ, which is why it is usually absent for USMTF coordinates: those are already canonical as typed.

Both rows matter on the standalone page, which is what mobile clients open. That page shows only the link, not the message it came from, so without the author's own text their spelling would be unreachable.

Customize your view

The link below the table lets you choose what the panel shows. Everything is on by default; untick what you never read and it is gone from every coordinate you open. Stored per person, so it changes nothing for anybody else.

The first entry is Map, which is not a row: it hides the picture above the table and leaves every reading in place. It is the one entry that takes something else with it, since the country is spoken by the map and appears nowhere else. The rest are the table's own rows, in the order the table lists them.

Two things follow from how it is stored, and both are deliberate. What is saved is the list of rows you hid, not the ones you kept, so a row added in a later version appears for you as well rather than being invisible to exactly the people who bothered to choose. And Restore defaults deletes your choice rather than writing today's rows into it, so you go back to tracking whatever the panel shows next.

Hiding every row is allowed. The panel keeps the note and the links at the bottom, and the same Customize your view link is how you get back.

The standalone page always shows every row.

The page a link opens outside the sidebar is rendered from the link alone and does not ask who is reading it. It and the sidebar can therefore show the same coordinate differently. The same is true of the DTG timezone table.

Copy icons

Every row carrying a value has a copy icon at its right edge: the grid reference, latitude and longitude, DMS, DDM, USMTF, UTM, the author's text and the normalized form. The rows that carry prose rather than a value do not, since copying about 11 m or WGS 84 gets you a sentence rather than a position.

The same icons appear on the standalone page, which is what mobile clients open. On both surfaces they are hidden when the browser cannot reach the clipboard, which is the case on any server reached over plain HTTP rather than HTTPS, and in the sidebar an icon is also absent while its own value has not arrived: offering one over converting… would put that on the clipboard. Every value stays selectable either way.

The icon changes to a tick for a moment once the value is on the clipboard, and the same acknowledgement is announced to screen readers. The button keeps its name across that change rather than renaming itself to "Copied", which would move it out from under a reader mid-sentence.

There is no map button. A map link would send a grid reference to a third party, which is an operational decision rather than a default, and this release does not make it.

No hover card

Pointing at a coordinate shows nothing, unlike a date-time group. The one thing a hover could usefully add is the grid reference, and this version can now compute one, but only on the server. A hover fires as the pointer crosses a link rather than on a click, so wiring one up would put a request behind every coordinate a reader's cursor passes over in a busy channel. A card that merely repeated the text already under the cursor would earn nothing, so there is none until it can show the grid without that cost.

Customize your view

Below the timezone table is a Customize your view link. It replaces the panel rather than expanding underneath it, because its timezone picker runs to several hundred rows and putting that below the table would bury the date-time group you opened the sidebar to read. A Back link returns without saving.

Two things are yours to set:

Timezones Which rows the table shows, up to 25. Chosen from a catalog of named military installations, or from every timezone your browser knows.
Flash threshold How close the instant has to be before the countdown flashes, in minutes. Between 1 and 1440.

Saving closes the editor, because the changed table behind it is the receipt. A save that fails does the opposite and stays open with the reason on screen, since closing would throw away both the message and your edits.

Restore defaults

Restore defaults deletes your settings rather than writing today's defaults into them. The difference matters: a reader who has never chosen keeps tracking whatever the defaults become, instead of being frozen at the list that happened to ship in this version.

For the same reason, a selection that is exactly the defaults collapses back to "nothing chosen" when you save it. Opening the editor and pressing Save does not quietly pin your table forever.

Your settings are per user

They are yours alone and follow you between clients. They are never shown to anyone else and never change what is stored in a message.

Choosing timezones

The picker is a combobox: type to filter, arrow keys to move, Enter to pick, Escape to close. Every term you type has to match, in any order, so berlin spang works. The identifier is searched both as written and with its separators opened out, so both america/los and los angeles find Los Angeles. The offset is searchable too, so +05:45 works.

The list has two groups:

  • Military installations, a curated catalog with names.
  • All timezones, every zone the browser knows, unnamed.

Several installations can share one timezone, and you can pick both.

Somebody at Stuttgart wants a row that says Stuttgart, not the Ramstein row that keeps the same clock. The two rows read identically to the minute, which is the accepted cost of naming both.

Names are never guessed from a timezone. Picking a bare Europe/Berlin out of "All timezones" gives a row reading Berlin, not Ramstein, so it cannot sit next to a real Ramstein row looking identical.

Row order

Rows are always ordered west to east by UTC offset, in the sidebar, the editor and the standalone page alike. The order you add them in carries no meaning and is not stored.

Offsets are measured at the date-time group's own instant, never looked up from a table. Roughly half of these zones observe daylight saving, so a stored offset would be an hour wrong for part of the year, and two rows can swap places between summer and winter. That is correct behavior, not a bug.

A zone whose offset cannot be measured sorts last rather than as UTC. Filing an unknown under Zulu would be a claim rather than an admission.

Nothing here may fail the panel

A settings read that fails, a stored blob that will not parse, and a timezone this browser cannot format each fall back to a default rather than taking the panel down. A save is the exception and reports its error, because a save that quietly did nothing is worse than one that says so. If you see a message when saving, Troubleshooting lists them all.
