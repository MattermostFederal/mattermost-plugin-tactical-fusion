Cursor on Target

The schema this build reads, what it refuses, and worked examples of every kind of event.

Settings: EnableCot and EnableCotFile. Every example on this page is one this build's own /tactical-fusion example-details posts, so what you read here is what your server will do.

A Cursor on Target event is rendered as a card rather than linked: the callsign and what the event says it is, the position, when it was taken and when it goes stale, and how accurately the position is known. The position is drawn on a map with its stated circular error around it, so a three metre fix and a nine kilometre fix do not look alike.

Posting an event

In a fenced code block

Paste the event into a fence labelled cot or xml:

<event version="2.0" uid="TGT-9F2A1C7B" type="a-h-G-U-C-A" how="h-e"
       time="2026-08-09T16:30:00Z" start="2026-08-09T16:30:00Z" stale="2026-08-09T16:32:00Z">
  <point lat="21.335300" lon="-157.948300" hae="4.0" ce="45.0" le="60.0"/>
  <detail>
    <contact callsign="TGT01"/>
    <link uid="ANDROID-88" relation="p-p" parent_callsign="ALPHA"/>
    <remarks>two vehicles, stationary</remarks>
  </detail>
</event>

Both labels are read the same way. Use cot when you mean it: a block labelled xml that turns out not to be an event is left alone silently, because plenty of XML is not Cursor on Target, while a block you labelled cot tells you why it was not rendered.

Without a fence

An event written on one line needs no fence at all: 

<event version="2.0" uid="TGT-9F2A1C7B" type="a-h-G-U-C-A" how="h-e" time="2026-08-09T16:30:00Z" start="2026-08-09T16:30:00Z" stale="2026-08-09T16:32:00Z"><point lat="21.335300" lon="-157.948300" hae="4.0" ce="45.0" le="60.0"/><detail><contact callsign="TGT01"/><link uid="ANDROID-88" relation="p-p" parent_callsign="ALPHA"/><remarks>two vehicles, stationary</remarks></detail></event>

Only the flat form is found without a fence.

An indented event is not. Four spaces of indentation is markdown's own syntax for a code block, and the plugin will not reach inside one. The indented example above is recognized because it is fenced, not in spite of it.

The <event> element

AttributeRequiredRead as
uidyesThe event's identity. Shown on the card, always.
typeyesDecoded into a label. See decoding the type.
timeyesWhen the event was taken. Must be RFC 3339.
startoptionalWhen it becomes valid. Shown on the card only when it differs from time.
staleoptionalWhen it expires. Drives the validity window and the countdown.
howoptionalHow the position was arrived at. See the how table.
versionignoredAccepted and never read.
accessignoredAccepted and never read.
qosignoredAccepted and never read.
opexignoredAccepted and never read.

Four attributes are accepted and ignored.

version, access, qos and opex are legal input and this build has no code path for any of them. They are never stored and never rendered. They are visible only in the As posted pane, which shows the event exactly as you wrote it. Nothing on the card is gated on access, so do not rely on it to mark an event restricted.

An event missing a uid, a type or a time is refused, and refusing it refuses the whole source. A duplicate attribute takes its first occurrence.

The <point> element

AttributeRangeRendered as
lat-90 to 90Position, and a link to the coordinate tools.
lon-180 to 180Position.
haeAny, including negativeAltitude (HAE), in metres.
ceNon-negativeAccuracy, circular. Drawn on the map as a circle.
leNon-negativeAccuracy, vertical.

Coordinates must be written as plain decimals. Go accepts hexadecimal and exponent notation where a browser's Number does not, and a value that validated on the server and read as NaN in the browser would leave the card and the map disagreeing.

What the card says about a position, in the order it decides:

The event saysThe card shows
No lat/lon, or not a plain decimal"The event states no position."
Outside the range of the earth"The event reports a position outside the range of the earth."
0,0The numbers, and a note that this is the value for a position that was never set. No pin.
Fewer than four decimal placesThe numbers, and a note that it is too coarse to link. No pin.
A good positionThe numbers, a link to the coordinate tools, and a pin.

9999999.0 means "not known".

Any value at or beyond it is treated as unstated and its row is left out entirely rather than printed as a very large number. Shape events use it routinely for ce and le.

Decoding the type

A type such as a-h-G-U-C-A is read left to right. The leading a means an atom, the next character is the affiliation, and everything after it is a path into the type table:

A repeated element takes its first occurrence, and a nested child is read only if that instance of its parent was accepted. An element under detail that is none of these is counted and reported, never dropped silently.

Some rows are convention rather than specification.

pdop, hdop, vdop and readiness are rendered exactly as stated because no specification this build could check pins them down. The same is true of the whole of geometry. Where a value is shown as stated, the card is repeating the event rather than vouching for it.

Shapes, circles and routes

Three kinds of event have content that is not a point. Their geometry is read and drawn on the map.

KindWritten asRead as
Drawn outlineshape > polyline > vertex, each with lat and lonAn ordered list of points. closed on the polyline makes it a ring.
Circle or ellipseshape > ellipse with major, minor, angleSemi-axes in metres, and a bearing clockwise from north.
Routelink elements carrying point="lat,lon"An ordered list of points.

A <link> is told apart by what it carries.

A link with a point is a route vertex. A link with a uid is a relation. They have separate budgets, so a long route cannot cost you the "Sent by" row and a relation cannot cost you a vertex.

A shape may cross the date line.

A shape that crosses 180 arrives as a jump from 179 to -179. It is drawn as one unbroken outline rather than as a line straight back across the whole map, and the map opens on the couple of degrees the shape actually occupies rather than on the whole planet. A route that circles the globe is the one case that cannot be framed more tightly than the world, and the map opens on the whole of it.

A shape is drawn, or it is not drawn and the sidebar says why.

There is no third option. A shape with more than 512 points would otherwise be shown as a line stopping somewhere the shape does not, and a shape with a point not written as a plain decimal would be shown missing a corner. Both are a different shape rather than a partial one, so neither is drawn. Everything else about the event, the callsign, the position, the times and the accuracy, is unaffected.

A shape that is not drawn

One vertex is written as 0x1p+3, which is a number Go accepts and a browser does not. The whole shape is refused rather than drawn with three corners out of four.

What this build refuses

LimitValuePast it
Source size64 KBThe source is refused.
Nesting depth32The source is refused.
Elements and attributes4,096 togetherThe source is refused.
Events in one source32The source is refused, never truncated. A card showing 32 of 200 events would be quietly wrong about what was posted.
Relations per event16The extras are dropped and the event is kept.
Vertices in a shape512The shape is not drawn and the event is kept.
Processing path hops16The oldest hops are dropped.
A field's length128 charactersTruncated, visibly.
Remarks1,024 charactersTruncated, visibly.

Three different answers there, and the difference is deliberate. A dropped relation costs one entry in a row that has already told you who sent the event. A truncated route draws a line that ends somewhere real routes do not. A partial batch misrepresents the post.

Sources that are refused outright

InputWhy
<!DOCTYPE event SYSTEM "cot.dtd">A document type declaration. Refused even behind a comment, and even inside <remarks>.
A processing instructionAnything other than a single leading <?xml ...?>.
&boom;There is no entity map, so an undefined entity is a syntax error. Entity expansion is impossible by construction.
encoding="UTF-16"No character set reader is registered. UTF-8 only.
<events><event/></events>The root must be event. Several events are written as siblings, with no wrapper.
<event/>No uid, type or time.
Not a real event: <event .../>Prose outside the root, on either side of it.
<event xmlns="urn:cot">Everything read must be in no namespace.
Invalid UTF-8Refused before parsing.

An ordinary XML comment is fine, including inside remarks. When a source is refused and you labelled the fence cot, the plugin tells you why, privately. A fence labelled xml is left alone silently.

What the card shows

A coloured dot for the affiliation, the callsign, what the event says it is, and the raw type in parentheses. Then, each row omitted when the event does not state it:

RowNotes
PositionLinked to the coordinate tools when it is precise enough.
Altitude (HAE)
AccuracyAlways shown, and says "Not stated" when it is not. An unstated accuracy is information.
TrackSpeed, and course where stated.
TimeLinked to the date-time tools.
Valid fromOnly when it differs from Time.
StaleWith how long the event was valid for.
FreshnessWhether it was already stale when it was posted.
Team, Sent by, Relates to, Source
UIDAlways shown.
RemarksSuppressed for a chat event, which shows them in its own line.

Four kinds of event get a one line summary above the detail: a chat event names its sender and room, a MEDEVAC counts its patients, a sensor states its field of view and range, and a video event says a stream exists without printing the address.

Nothing on the card ticks.

Every time on it is absolute Zulu, computed on the server. The one live countdown in this feature is the Goes stale row in the sidebar, which is counted against your own device's clock and says so.

GroupContains

ShapeKind, route attributes, point count, axes and orientation, and the reason a shape was not drawn.

The map

The marker is a crosshair rather than a dot, because a crosshair says "this point" where a dot says "somewhere around here". Its colour is the affiliation.

A stated ce is drawn as a circle around the position, sized in metres and redrawn at every zoom so it keeps its size on the ground rather than on the screen. Its label is the same string the card shows, never re-rounded. An event with no ce gets a pin and no circle: no default radius is invented.

The circle and any geometry are drawn for a single event only. A card listing several events shows their positions and no accuracy rings.

The map obeys EnableLocationMapInline and your own inline-map preference. There is deliberately no Cursor on Target map switch of its own.

What the card will not claim

It will notBecause
Name the countryAn event states no country. A derived one, printed beside ce and hae, would read as something the event reported.
Pin 0,0That is the value for a position that was never set. The numbers are shown; the pin is not.
Re-round a readingA stated 0.4 stays 0.4 m everywhere, including for a screen reader.
Colour the marker from colorThe marker carries affiliation. A stated display colour is shown as its own swatch.
Link a video addressAuthor text is never turned into a link by this card.
Reshape an atom from its detailA __chat or _medevac_ element inside an a- contact report does not turn it into a chat or a MEDEVAC.

A card is frozen at the moment it was posted.

What it shows was computed when the message arrived and stored with it. A later build with a corrected type table does not reach a card already posted. Editing the message makes the card fall back to showing the text, because the card can no longer vouch for matching it.

Settings and troubleshooting

SettingGoverns
EnableCotWhether an event becomes a card at all.
EnableCotFileWhether an attached file is read.

A card changes what the post is.

Rendering an event sets the post's type, and a typed post loses its Elasticsearch and OpenSearch matches, its auto-translation, its embeds and its file attachment list. EnableCot is how an install opts out. A post carrying an event is also never decorated, so a coordinate written beside one is not linked.

If an event you posted did not render, see Troubleshooting.
