Airfields

Two label-only grammars, an embedded database of 19,280 fields with their runways and frequencies, and the reason a bare code is never linked.

Settings: EnableAirport and EnableAirportTable. To see what your own server does, run /tactical-fusion examples. Every example below is one of that command's own rows.

The grammar

Four upper case letters, behind one of four USMTF field labels. That is the whole grammar, and there is no second form:

ExampleNotes
ICAO:PHNLDaniel K. Inouye International, Honolulu
LOC:PGUMAntonio B. Won Pat International, Guam
DEPLOC:PHTOthe departure airfield of a USMTF air movement
ARRLOC:PHIKand the arrival airfield
DEPLOC:PGUA//a set line ends //, which is kept out of the link
ICAO :NZSPa space before the colon is optional

The labels are ICAO, LOC, DEPLOC and ARRLOC, sorted longest first so DEPLOC cannot lose to LOC. In USMTF these introduce a facility whose position is looked up rather than computed, which is why the coordinate decorator deliberately does not claim them.

The label is matched and then dropped, so only the code becomes the link text. A set line's trailing // is preserved: DEPLOC:PGUA// keeps its terminator.

The IATA grammar

A three letter IATA code is read behind its own label, IATA:, in upper case, and opens the same panel the ICAO code does:

ExampleNotes
IATA:HNLDaniel K. Inouye International, which is PHNL
IATA:LAX//the set terminator is kept out of the link, as it is for an ICAO code
IATA:QQQdeclined: no field carries that code
iata:hnldeclined: the label and the code are upper case only
HNLdeclined: there is no bare grammar, and never will be

The link carries the IATA code the author wrote, and the panel resolves it to the ICAO ident on every open. Three letters collide with ordinary words even more often than four do, so everything below applies with more force. A code the database holds twice is dropped from both fields when the data is built, so one code names one airfield or none.

Why a bare code is never linked

A four letter upper case word is what prose is made of. Of the 19,280 codes this build carries, 349 are ordinary English words:

CodeIs alsoThe airfield
FACTa factCape Town International
FASTfastSomerset East
LIMAthe phonetic letterTorino-Aeritalia
UNITa unitTura Mountain
USCGthe Coast GuardChelyabinsk Shagol
ETICestimated time in commissionGrafenwöhr AAF

the USCG cutter is inbound must not become a link to a Russian airfield, and that was a KIND thing to do must not become a link to Indianapolis. Decoration rewrites the stored message permanently, so the label is required rather than merely preferred.

The label is upper case only.

Unlike every coordinate label, which is case insensitive, this one is not. loc: fast turnaround on the ramp would otherwise link the word fast. The trade is that icao:kind is declined, and that is the right way round.

Validation is a lookup, not a shape

A code has to be in the database, not merely look like one. That is what makes ICAO:FAST a link to Somerset East while ICAO:QZQZ is declined.

A code this build does not hold still opens its page.

The page says the code is not in this build's database rather than returning an error. A refreshed dataset that drops a code must not turn every message naming it into a permanently broken link.

Deliberately declined

ExampleNotes
KINDa bare code is indistinguishable from a word, and KIND is one
USCGand this one is Chelyabinsk Shagol, in Russia
FACTCape Town International, which is why nothing bare is read
icao:kinda lower-case label would reach words in ordinary prose
ICAO:QZQZfour letters this plugin's airfield database does not hold
ICAO:KINan ICAO ident is four letters
logs/ICAO:KINDa label inside a path is not a field label
LOC: FASTnothing after the colon, or ordinary capitalized prose would be rewritten

logs/ICAO:KIND is worth singling out. A label with a path character in front of it is not a field label, and rewriting the middle of a path is exactly what the boundary rules exist to prevent. The same applies to see_ICAO:KIND and x-ICAO:KIND.

A label cannot reach across a line break either, so Divert to LOC: followed by FAST movers inbound on the next line is left alone.

What the panel shows

Clicking an airfield code opens the right-hand sidebar. See the sidebar panel for the shared mechanics.

RowShowsExample
CodeThe ICAO ident.KIND
PlaceMunicipality, subdivision and country. This row is the coordinate link.Indianapolis, IN, US
UseThe military designator in the field's name, where there is one.Military (Air Force Base)
TypeThe size class from the database.Large Airport
ElevationFeet above sea level, where stated.797 ft
IATAThe three letter code, where the field has one.IND

A row with no value is left out entirely rather than shown empty. Elevation is genuinely absent for 1,444 fields, which is why it is distinguished from an elevation of zero.

The panel draws the position as a map and hands the coordinate to the coordinate panel for the readings, rather than reprinting them here. Clicking Place is what does it.

Runways and frequencies

Under the table the panel lists the field's runways and its published frequencies, each section left out entirely when the database lists none. A runway row is its designation and what is known about it: length by width in feet, the surface, and whether it is lighted or closed. A frequency row is its type, a description where the database has one, and the value in megahertz to three decimals, with a copy button.

SectionExample row
Runways08L/26R 12,360 x 200 ft, Asphalt
FrequenciesTWR 118.100

The lighting flag is shown only when the database sets it. An unset flag is not a statement that a runway is unlit, so nothing says so.

The map

The map under the details draws the field's reference point, and each runway whose two ends the database places as a line in the airfield color. Open larger opens the same picture full window at /map?airport=PHNL, which is addressed by the ident alone and re-reads the database when it opens.

The position is a reference point.

The database gives one position per field, quoted to four decimal places, which is about 11 meters. It is a reference point for the field rather than a surveyed location of the tower, the threshold, or any particular part of it.

The table under a code-only message

Setting: EnableAirportTable

A message whose whole text is one airfield token is expanded into a markdown table in the stored message:

AirfieldIndianapolis International Airport
CodeKIND
PlaceIndianapolis, IN, US
TypeLarge Airport
Elevation797 ft
IATAIND
Runways05L/23R 11,200 x 150 ft, Concrete; 05R/23L 10,000 x 150 ft, Concrete; 14/32 7,605 x 150 ft, Asphalt
FrequenciesATIS 134.250; GND 121.900; TWR 120.900

A Use row carries the military designator where the name has one, and the Runways and Frequencies rows are left out for a field the database lists none for. The Code row carries the author's own token, including a set line's //, which is what keeps searching for the code finding the post.

Why a table rather than a card.

Writing markdown into the message keeps the post ordinary: it keeps its Elasticsearch and OpenSearch matches, its link previews and its translation, and it renders on clients that never load the plugin's webapp. The cost is that the expansion is permanent and frozen at the moment it was posted, so a later database update does not reach it.

The map under a message of nothing but airfield codes

Setting: EnableAirportRoute

A message whose whole text is labeled airfield references, on one line or one per line, keeps its links and gains a map under the post with every airfield marked, a numbered legend that opens each airfield's panel, and a leg drawn between each consecutive pair in message order:

MessageResult
DEPLOC:PHIK ARRLOC:PGUA//two links, and a map with 1 and 2 and the leg between them
ICAO:PHIK IATA:HNL LOC:PGUAthree links, and a map with three markers and two legs
DEPLOC:PHIK, ARRLOC:PGUAtwo links and no map: the comma is prose between the codes
DEPLOC:PHIK 091630ZAUG26two links and no map: not every token is an airfield
ICAO:PHIKthe table while that is on; a one-airfield map when it is off

A leg is a straight line between consecutive airfields in the order they were written, and the map says so. It is not a route somebody stated. Up to 64 airfields are drawn; a longer message keeps its links and gets no map. Open larger opens the same map full window.

This sets the post's type.

A post with the map under it is excluded from Elasticsearch and OpenSearch results and from Recent Mentions, loses its link previews and is not auto-translated, exactly as the map under a lone coordinate is. The links in the message are still there, and the airfield names stay searchable nowhere but in the map's legend. Turn the setting off to keep such posts ordinary.

Where the data comes from

The database is compiled into the plugin, so lookups need no network. It carries 19,280 fields with an ident, a name, a type, a place, a country, an IATA code where one exists, an elevation where one is stated, a position, and the military designator in the name where there is one, plus 18,255 runways and 25,915 frequencies from the same source. Provenance is recorded beside the data in the repository rather than printed in the panel.

Settings and troubleshooting

SettingGoverns
EnableAirportThe whole decorator. There is no separate label switch, because the grammar is label-only by construction.
EnableAirportIATAThe IATA grammar. Only applies while EnableAirport is on.
EnableAirportTableThe table under a code-only message.
EnableAirportRouteThe map under a message of nothing but airfield codes. Also needs the map under a post to be on.
