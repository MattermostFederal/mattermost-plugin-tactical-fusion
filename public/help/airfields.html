Airfields

One label-only grammar, an embedded database of 19,012 fields, and the reason a bare code is never linked.

Settings: EnableAirport and EnableAirportTable. To see what your own server does, run /tactical-fusion example-details. Every example below is one of that command's own rows.

The grammar

Four upper case letters, behind one of four USMTF field labels. That is the whole grammar, and there is no second form:

ExampleNotes
ICAO:PHNLDaniel K. Inouye International, Honolulu
LOC:PGUMAntonio B. Won Pat International, Guam
DEPLOC:PHTOthe departure airfield of a USMTF air movement
ARRLOC:PHIKand the arrival airfield
DEPLOC:PGUA//a set line ends //, which is kept out of the link
ICAO :NZSPa space before the colon is optional

The labels are ICAO, LOC, DEPLOC and ARRLOC, sorted longest first so DEPLOC cannot lose to LOC. In USMTF these introduce a facility whose position is looked up rather than computed, which is why the coordinate decorator deliberately does not claim them.

The label is matched and then dropped, so only the code becomes the link text. A set line's trailing // is preserved: DEPLOC:PGUA// keeps its terminator.

Why a bare code is never linked

A four letter upper case word is what prose is made of. Of the 19,012 codes this build carries, 343 are ordinary English words:

CodeIs alsoThe airfield
FACTa factCape Town International
FASTfastSomerset East
LIMAthe phonetic letterTorino-Aeritalia
UNITa unitTura Mountain
USCGthe Coast GuardChelyabinsk Shagol
ETICestimated time in commissionGrafenwöhr AAF

the USCG cutter is inbound must not become a link to a Russian airfield, and that was a KIND thing to do must not become a link to Indianapolis. Decoration rewrites the stored message permanently, so the label is required rather than merely preferred.

The label is upper case only.

Unlike every coordinate label, which is case insensitive, this one is not. loc: fast turnaround on the ramp would otherwise link the word fast. The trade is that icao:kind is declined, and that is the right way round.

Validation is a lookup, not a shape

A code has to be in the database, not merely look like one. That is what makes ICAO:FAST a link to Somerset East while ICAO:QZQZ is declined.

A code this build does not hold still opens its page.

The page says the code is not in this build's database rather than returning an error. A refreshed dataset that drops a code must not turn every message naming it into a permanently broken link.

Deliberately declined

ExampleNotes
KINDa bare code is indistinguishable from a word, and KIND is one
USCGand this one is Chelyabinsk Shagol, in Russia
FACTCape Town International, which is why nothing bare is read
icao:kinda lower-case label would reach words in ordinary prose
ICAO:QZQZfour letters this plugin's airfield database does not hold
ICAO:KINan ICAO ident is four letters
logs/ICAO:KINDa label inside a path is not a field label
LOC: FASTnothing after the colon, or ordinary capitalized prose would be rewritten

logs/ICAO:KIND is worth singling out. A label with a path character in front of it is not a field label, and rewriting the middle of a path is exactly what the boundary rules exist to prevent. The same applies to see_ICAO:KIND and x-ICAO:KIND.

A label cannot reach across a line break either, so Divert to LOC: followed by FAST movers inbound on the next line is left alone.

What the panel shows

Clicking an airfield code opens the right-hand sidebar. See the sidebar panel for the shared mechanics.

RowShowsExample
CodeThe ICAO ident.KIND
PlaceMunicipality, subdivision and country. This row is the coordinate link.Indianapolis, IN, US
TypeThe size class from the database.Large Airport
ElevationFeet above sea level, where stated.797 ft
IATAThe three letter code, where the field has one.IND

A row with no value is left out entirely rather than shown empty. Elevation is genuinely absent for 1,444 fields, which is why it is distinguished from an elevation of zero.

The panel draws the position as a map and hands the coordinate to the coordinate panel for the readings, rather than reprinting them here. Clicking Place is what does it.

The position is a reference point.

The database gives one position per field, quoted to four decimal places, which is about 11 metres. It is a reference point for the field rather than a surveyed location of the tower, the threshold, or any particular part of it.

The table under a code-only message

Setting: EnableAirportTable

A message whose whole text is one airfield token is expanded into a markdown table in the stored message:

AirfieldIndianapolis International Airport
CodeKIND
PlaceIndianapolis, IN, US
TypeLarge Airport
Elevation797 ft
IATAIND

The Code row carries the author's own token, including a set line's //, which is what keeps searching for the code finding the post.

Why a table rather than a card.

Writing markdown into the message keeps the post ordinary: it keeps its Elasticsearch and OpenSearch matches, its link previews and its translation, and it renders on clients that never load the plugin's webapp. The cost is that the expansion is permanent and frozen at the moment it was posted, so a later database update does not reach it.

Where the data comes from

The database is compiled into the plugin, so lookups need no network. It carries 19,012 fields with an ident, a name, a type, a place, a country, an IATA code where one exists, an elevation where one is stated, and a position. Provenance is recorded beside the data in the repository rather than printed in the panel.

Settings and troubleshooting
