Troubleshooting

Symptoms, causes, and fixes. Codes link into the registry.

A time was not turned into a link

Working from most to least likely:

CauseHow to tellFix
The format is not one that is recognised Compare against the declined list. Epoch seconds, 12 hour clocks, bare dates and CST style abbreviations are all deliberately absent. Write it as a date-time group or an RFC 3339 timestamp.
It is inside a protected span It sits in a code fence, inline code, a link, or inline HTML. Working as intended. Move it into ordinary prose if you want it linked. See protected spans.
The format is switched off Run /tactical-fusion examples. It ends with a note when decoration is off, and shows each format's real result. Turn the format on in System Console, Plugins, Tactical Fusion.
The message was edited The time was added or changed in an edit rather than the original post. Working as intended. Edits are stored verbatim, on purpose, so the plugin never transforms text you deliberately authored.
The message predates the plugin It was posted before the plugin was installed or enabled. Working as intended. There is no backfill; only new posts pass through the hook.
The message would have been too long Server log carries TF-11001. Working as intended. Decorating would have pushed the post over the maximum size, so it was posted undecorated rather than rejected. Shorten the message or split it.
A decorator panicked Server log carries TF-11000. A genuine bug. The post was left unmodified, so nothing was lost. Report it with the log line.

Nobody else sees the link, or only some clients do

The link is in the stored message, so every client sees the same text. What differs is what happens on clicking it: clients running the plugin's web bundle open the sidebar, and everything else follows the link to the server-rendered page. Both show the same instant.

Editing a post shows markdown instead of the time I typed

Working as intended, and the main cost of decorating on the server. The link is the stored text. Deleting the link syntax while editing is the supported way to opt one post out; the plugin will not put it back.

Old links return "Not found"

CodeCauseFix
TF-12001 The plugin is disabled or removed, so nothing serves the route any more. Re-enable the plugin. To stop new decoration while keeping the history working, switch EnableDTG off instead of disabling the plugin.
TF-12002 The request landed while the plugin was still activating. Reload the page. If it persists, the plugin is failing to activate; check the server log for TF-10000.
TF-12003 The link names a decorator type this build does not have, usually a link written by a newer version. Upgrade the plugin.

"That link is missing or has an invalid date-time group"

Code TF-17000. The query string carries no usable instant. Almost always a hand-edited or truncated URL, or a link copied out of a message and reassembled by something that mangled the query string. Click the original link in the channel rather than a copy.

The panel and the standalone page show different timezones

Expected if you have customised your view. The standalone page is served without a Mattermost session, so it has no reader to ask and always shows the built-in defaults. There is no fix; it is inherent to a page that has to work for a client with no login.

Two timezone rows swapped places

Expected across a daylight saving boundary. Rows are ordered west to east by the offset measured at the date-time group's own instant, so two zones that observe daylight saving differently will genuinely change places between summer and winter. London and Reykjavik are the usual pair.

My new timezones did not appear

SymptomCauseFix
The table updated for a while, then reverted You are on a cluster and one node missed the cache invalidation. Server log carries TF-15000. It corrects itself within ten minutes when the cache entry expires. Persistent occurrences mean cluster messaging is not working.
The table shows the defaults and never changed The stored settings could not be parsed. Server log carries TF-14007. Open the editor and save again. The next save replaces the unreadable blob.

Messages when saving your view

A failed save stays open with the reason on screen, rather than closing and losing your edits. Every message below carries its code.

MessageCodeCause and fix
Not authorized. TF-13000 Your session expired. Reload Mattermost and sign in again.
Not ready. TF-13002 The plugin was still activating. Try again in a moment.
That is not a valid settings payload. TF-13005 The request body was not decodable or exceeded the size cap. Not reachable from the editor; it means something other than the sidebar sent the request.
Could not read your settings. TF-13004 The plugin key-value store could not be read. A server side problem; check the log for the matching line.
Could not save your settings. TF-13006 The store could not be written. As above.
Could not restore the defaults. TF-13007 The stored blob could not be deleted. As above.
at most N timezones may be selected TF-14005 Remove some rows. The count is taken after duplicates are collapsed.
the flash threshold must be between N and N minutes TF-14006 Choose a value in range. Clearing the field entirely means "use the default", which is always accepted.
"Local" is not a timezone identifier TF-14003 Pick a real zone. Local means whatever zone the server process runs in, which is not a place and can differ between nodes.
unknown timezone "..." TF-14004 Your browser offered a zone the server's timezone database does not have. Pick a neighbouring zone and report the identifier.
"..." is not a timezone identifier TF-14002 Not reachable from the picker; it means something other than the sidebar sent the request.
a timezone label may be at most N characters TF-14000 As above.
a timezone label may not contain control characters TF-14001 As above.

The plugin will not activate

Check the server log for TF-10000. It means two decorators claimed the same type, or one declared an empty type. That is a build problem rather than a configuration one, so report it with the version number.

Reporting something not listed here

Include, if you have them:

  • The TF-NNNN code, from the message or the server log
  • The exact text you typed, and what was stored
  • The output of /tactical-fusion examples, which shows the live behaviour of your server
  • Which of the four settings are on
