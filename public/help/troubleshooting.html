Troubleshooting

Symptoms, causes, and fixes. Codes link into the registry.

A time was not turned into a link

Working from most to least likely:

CauseHow to tellFix
The format is not one that is recognized Compare against the declined list. Epoch seconds, 12 hour clocks, bare dates and CST style abbreviations are all deliberately absent. Write it as a date-time group or an RFC 3339 timestamp.
It is inside a protected span It sits in a code fence, inline code, a link, or inline HTML. Working as intended. Move it into ordinary prose if you want it linked. See protected spans.
The format is switched off Run /tactical-fusion example-details. It ends with a note when decoration is off, and shows each format's real result. Turn the format on in System Console, Plugins, Tactical Fusion.
The message was edited The time was added or changed in an edit rather than the original post. Working as intended. Edits are stored verbatim, on purpose, so the plugin never transforms text you deliberately authored.
The message predates the plugin It was posted before the plugin was installed or enabled. Working as intended. There is no backfill; only new posts pass through the hook.
The message would have been too long Server log carries TF-11001. Working as intended. Decorating would have pushed the post over the maximum size, so it was posted undecorated rather than rejected. Shorten the message or split it.
A decorator panicked Server log carries TF-11000. A genuine bug. The post was left unmodified, so nothing was lost. Report it with the log line.

A coordinate was not turned into a link

Run /tactical-fusion check <your text>. It runs the real matcher against exactly that text and reports what it did, without posting anything. That answers this question directly and is faster than working through the list below.

The usual causes, in the order they come up:

SymptomCauseFix
34.05, -118.25 did nothing, but 34.0561, -118.2500 works Signed decimal degrees needs at least four decimals on both values. Write the full precision, or add hemisphere letters: 34.05 N, 118.25 W is accepted.
A coordinate at the end of a sentence did nothing A full stop or comma directly against the last digit is indistinguishable from a range or a list at the point the check runs. Put a space before the punctuation, or accept it. This is a deliberate trade against rewriting the middle of -118.2500..-118.2600.
35N079W did nothing The shortest USMTF shape is only matched behind a field label. Write LATD:35N079W.
18suj2347806483 did nothing, but 18SUJ2347806483 works A run-together grid reference has to be upper case. Lower-case hexadecimal of that shape is what a short git commit hash looks like, and about one in 3,900 of them is a valid grid reference. Write it in upper case, space it out, or write MGRS: in front.
18SUJ2306 did nothing, but 18SUJ234064 works A run-together reference needs at least three digits per axis, a 100 m square. Shorter runs are what part numbers look like: 26HMA1997 is a valid grid reference, and about one uppercase run in 75,000 collides at two digits. Space it as 18S UJ 23 06, or write MGRS:18SUJ2306.
33U2910005628000 did nothing, but 33U 291000 5628000 works UTM run together has no letters to check: after the zone and band it is thirteen bare digits. Space it out, or write UTMO: in front.
A UTM position did nothing, but MGRS and lat/lon work UTM is off by default, and is the only format that is. Its band letter is ambiguous, so a wrong reading is a confidently misplaced position rather than a missed decoration. An admin turns on EnableLocationUTM in the System Console. Read that section first: it explains when the default is the right one for your workspace.
A UTM position opened on a latitude nowhere near the one intended The letter after the zone is read as a latitude band, never as a hemisphere, so 11S is band S (34 north) and not "zone 11, southern hemisphere" (56 south). A southern-hemisphere position written that way is usually declined, because its northing does not land in the band, but not always. Write southern positions as a grid reference, or as latitude and longitude. Delete the link while editing the post to opt that one message out.
A grid reference with plausible-looking letters did nothing Only eight of the twenty-four 100 km column letters are legal in any given zone, and the row letters are staggered in even-numbered zones. 32WDL123123 names no real square. Check the letters against the zone. check will confirm.
A polar coordinate has no grid rows Above 84° north and below 80° south there is no UTM grid. That is Universal Polar Stereographic, a different system this plugin does not implement. Nothing to do. The coordinate is still decorated and still shows latitude and longitude.
One coordinate in a list linked and the others did not A coordinate directly adjacent to another number is read as part of a numeric list. Separate them with something other than a comma and a space, or put each on its own line.
Nothing in the message linked, including a coordinate you are sure of The format, or coordinate decoration as a whole, is switched off. Check the admin settings. check reflects them, so it will say nothing matched.

The panel shows fewer decimals than I typed

It shows what the original text carried, and no more. A coordinate written to two decimals is only good to about a kilometer, so rendering it back at six would invent precision that was never there.

If the panel is coarser than you expected, the coordinate in the message is coarser than you expected. The As written row shows exactly what was parsed.

Nobody else sees the link, or only some clients do

The link is in the stored message, so every client sees the same text. What differs is what happens on clicking it: clients running the plugin's web bundle open the sidebar, and everything else follows the link to the server-rendered page. Both show the same instant.

Editing a post shows markdown instead of the time I typed

Working as intended, and the main cost of decorating on the server. The link is the stored text. Deleting the link syntax while editing is the supported way to opt one post out; the plugin will not put it back.

Old links return "Not found"

CodeCauseFix
TF-12001 The plugin is disabled or removed, so nothing serves the route any more. Re-enable the plugin. To stop new decoration while keeping the history working, switch EnableDTG off instead of disabling the plugin.
TF-12002 The request landed while the plugin was still activating. Reload the page. If it persists, the plugin is failing to activate; check the server log for TF-10000.
TF-12003 The link names a decorator type this build does not have, usually a link written by a newer version. Upgrade the plugin.

"That link is missing or has an invalid date-time group" or "invalid coordinate"

Code TF-17000 for a date-time group, TF-17001 for a coordinate. The query string carries no usable instant or no usable position. Almost always a hand-edited or truncated URL, or a link copied out of a message and reassembled by something that mangled the query string. Click the original link in the channel rather than a copy.

The sidebar says "Not a coordinate"

Code TF-13008. The server was asked to convert the coordinate in that link and answered that it is not one this plugin issued. The panel refuses to render anything rather than showing a position that may name somewhere else entirely, which is the same thing the standalone page does for the same link.

Almost always a hand-edited or reassembled URL. If you see it on a link you clicked directly in a channel and did not edit, that is worth reporting with the code and the link.

This is distinct from the grid rows reading unavailable, which means the request did not arrive at all. That leaves the rest of the panel intact and usually clears on reopening.

The panel and the standalone page show different timezones

Expected if you have customised your view. The standalone page is served without a Mattermost session, so it has no reader to ask and always shows the built-in defaults. There is no fix; it is inherent to a page that has to work for a client with no login.

Two timezone rows swapped places

Expected across a daylight saving boundary. Rows are ordered west to east by the offset measured at the date-time group's own instant, so two zones that observe daylight saving differently will genuinely change places between summer and winter. London and Reykjavik are the usual pair.

My new timezones did not appear

SymptomCauseFix
The table updated for a while, then reverted You are on a cluster and one node missed the cache invalidation. Server log carries TF-15000. It corrects itself within thirty minutes when the cache entry expires. Persistent occurrences mean cluster messaging is not working.
The table shows the defaults and never changed The stored settings could not be parsed. Server log carries TF-14007. Open the editor and save again. The next save replaces the unreadable blob.

A slash command refused to run

Every refusal below is ephemeral, so only you see it and nothing is written to the channel. All of them carry a code.

MessageCodeCause and fix
Unknown subcommand. Available: examples, example-details, check TF-16000 A typo, or a subcommand from a newer version. The list in the message is what this build has; see Commands.
Decorators are not registered yet. Try again once the plugin has finished activating. TF-16001, TF-16002, TF-16005 The command ran between the plugin being enabled and OnActivate finishing. Wait a moment and run it again. Three codes because the same condition is reached through examples, check and example-details respectively, and knowing which one asked is worth a code. If it persists, the plugin did not activate: see below.
Nothing would be decorated, so there is nothing to show. Every format is switched off in the System Console, under Plugins > Tactical Fusion. TF-16003 Exactly what it says, and it is a refusal rather than an empty post on purpose: a message advertising the plugin while demonstrating nothing would be permanent. Turn a format on in Admin settings.
The examples do not fit in one post on this server. Run /tactical-fusion example-details instead, which spreads itself over several posts. TF-16004 examples is one post by definition, so it measures itself against the smallest limit any store reports and refuses rather than letting the server reject it. A long install subpath reaches this, because every link in the post carries it.
There are no examples to post. TF-16006 Not reachable in a normal build: every set has rows. Report it with the version.
Could not post the examples to this channel: ... TF-16006 The server refused the first post, and the text after the colon is its own reason. The command has already retried at a smaller size by the time you see this, so a length complaint here means something other than the post limit. Nothing was written to the channel, so nothing needs cleaning up.
N of M messages could not be posted, so the examples are incomplete. TF-16006 The first post landed and a later one did not, so the channel has part of the set. The rest were still attempted rather than abandoned. Delete what arrived and run it again.

Messages when saving your view

A failed save stays open with the reason on screen, rather than closing and losing your edits. Every message below carries its code.

MessageCodeCause and fix
Not authorized. TF-13000 Your session expired. Reload Mattermost and sign in again.
Not ready. TF-13002 The plugin was still activating. Try again in a moment.
That is not a valid settings payload. TF-13005 The request body was not decodable or exceeded the size cap. Not reachable from the editor; it means something other than the sidebar sent the request.
Could not read your settings. TF-13004 The plugin key-value store could not be read. A server side problem; check the log for the matching line.
Could not save your settings. TF-13006 The store could not be written. As above.
Could not restore the defaults. TF-13007 The stored blob could not be deleted. As above.
at most N timezones may be selected TF-14005 Remove some rows. The count is taken after duplicates are collapsed.
the flash threshold must be between N and N minutes TF-14006 Choose a value in range. Clearing the field entirely means "use the default", which is always accepted.
"Local" is not a timezone identifier TF-14003 Pick a real zone. Local means whatever zone the server process runs in, which is not a place and can differ between nodes.
unknown timezone "..." TF-14004 Your browser offered a zone the server's timezone database does not have. Pick a neighboring zone and report the identifier.
"..." is not a timezone identifier TF-14002 Not reachable from the picker; it means something other than the sidebar sent the request.
a timezone label may be at most N characters TF-14000 As above.
a timezone label may not contain control characters TF-14001 As above.
"..." is not a row of the location panel TF-14008 The saved view named a row this version does not have. Not reachable from the editor, which offers one checkbox per row that exists. Note the asymmetry: writing an unknown row is refused, but reading one is not, so retiring a row can never lock you out of your own settings.

The plugin will not activate

Check the server log for TF-10000 or TF-10001. TF-10000 means two decorators claimed the same type, or one declared an empty type; TF-10001 means the slash command could not be registered, which usually means another plugin already claims the same trigger. Both are build or install problems rather than configuration ones, so report either with the version number.

Reporting something not listed here

Include, if you have them:

  • The TF-NNNN code, from the message or the server log
  • The exact text you typed, and what was stored
  • The output of /tactical-fusion example-details, which shows the live behavior of your server
  • Which settings are on. There are eleven, and one of them, EnableLocationUTM, is off until an admin turns it on
