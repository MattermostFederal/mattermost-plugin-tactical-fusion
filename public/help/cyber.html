Cyber Context

Five kinds of security indicator, two catalogs built into the plugin, and datasets an operator syncs in. Nothing is ever fetched from the internet.

Settings: EnableCyber and the five kind switches under it, plus CyberDatasetsDir. To see what your own server does, run /tactical-fusion examples. Every example below is one of that command's own rows.

The five kinds

Each kind is recognized in ordinary prose, with no label in front of it, and each has its own switch. What is written stays written: the link's text is your own token, and only the address behind it carries the canonical spelling.

KindExampleRecognized by
Vulnerability CVE-2025-55182 Shape, in any case, for a year of 1999 or later
Weakness CWE-79 The CWE catalog built into the plugin, in any case
MITRE ATT&CK T1059.001 and TA0002 The ATT&CK catalog built into the plugin, upper case only
IP address 8.8.8.8 and 141.98.9.137 A parsed IPv4 or IPv6 address, minus loopback and unspecified
File hash ed01ebfbc9eb5bbea545af4d01bf5f1071661840480439c6e5babe8e080e41aa A 32, 40 or 64 digit hexadecimal run

Post a sentence with an indicator in it and the indicator becomes a link: 

Patched CVE-2021-44228 across the fleet, beacon was to 203.0.113.7

The stored text is the token you typed.

Writing cve-2021-44228 in lower case stores a link reading cve-2021-44228. The canonical spelling, CVE-2021-44228, travels in the address only, so the panel and the page agree about which vulnerability it is while your message still reads the way you wrote it.

Vulnerability identifiers

Setting: EnableCyberCVE

CVE-2021-44228 is recognized by shape rather than by lookup, in any case, with a four digit year of 1999 or later and four to seven digits after it. Identifiers are issued daily and no list of them ships inside the plugin, so requiring a lookup would mean this week's vulnerability never linking. An identifier the installed datasets do not hold still links, and its panel says so rather than refusing.

What the panel shows about one comes from the datasets: a summary and a CVSS score from cve.tsv, a probability of exploitation from epss.tsv, and whether it is in the known-exploited catalog from kev.tsv. Weaknesses the vulnerability record names are offered as CWE links.

With cvedetail.tsv installed the panel and the page also show, each in a section that opens on a click and says how many lines it holds: the products and versions the reporting organization lists as affected, the product configurations NVD lists, and the references, each with its tags such as Patch, Exploit or Vendor Advisory. A row names which organization reported each weakness. A reference opens in a new tab, and only a http or https address is ever shown as a link. On an air-gapped network a reference will not load, but it still names the advisory to ask for.

Weakness identifiers

Setting: EnableCyberCWE

CWE-79 is recognized in any case, and validated against the CWE catalog built into the plugin. A number the catalog does not hold is left exactly as written, which is why CWE-99999 is plain text. The panel gives the weakness its name, its abstraction level, its status, a summary, and links to the parents above it.

MITRE ATT&CK identifiers

Setting: EnableCyberAttack

Techniques, sub-techniques and tactics are all read: T1059 is a technique, T1059.001 one of its sub-techniques, and TA0002 a tactic. Like CWE, these are validated against the catalog built into the plugin, so an identifier that names nothing is left as written.

ATT&CK identifiers are upper case only.

Unlike CVE and CWE, which are read in any case, t1059 is not an ATT&CK identifier here. A lower-case t followed by four digits is a part number, a ticket and a serial number far more often than it is a technique.

The panel names the technique, says which kind it is, lists its tactics, links to its parent and its sub-techniques, and gives the reference address at attack.mitre.org. That address is derived from the identifier rather than carried in the catalog, so a link that reaches a reader is never one somebody else chose.

IP addresses

Setting: EnableCyberIP

An IPv4 or IPv6 address is recognized when it genuinely parses as one. The panel gives its version and its scope, which is the one thing no dataset has to supply: global, private, loopback, link-local, multicast, carrier-grade NAT or documentation. 203.0.113.7 is a documentation address, so no dataset describes it and the panel says which it is.

Where the datasets have something to add, the autonomous system, the country, the region and the city come from ip.tsv or from a vendor .mmdb database an operator dropped in.

141.98.9.137 is the example of an address from an incident: CISA's advisory AA23-325A lists it as the remote address LockBit 3.0 affiliates used to exploit Citrix Bleed. Its panel lists that under Threat reports, linked to the advisory, and its hover says Reported malicious. The indicators of the CISA advisories the plugin ships with come in the bundle; addresses and file hashes from abuse.ch ThreatFox and Feodo Tracker, and the Tor exit list, come from threat.tsv, and malware samples from abuse.ch MalwareBazaar from malware.tsv, when an operator installs them. Every report names its source, and a Tor exit is shown as context rather than as a verdict. Your team's own judgments belong in the watchlist. Hosting addresses are reassigned, so one named in an old advisory may belong to somebody else today.

A four-part version number cannot be told apart from an address.

1.2.3.4 is a valid address and a common version number, and nothing in the text says which was meant. It is read as an address. An install where that matters more than the enrichment does can turn this one kind off and leave the other four on. A version written the way versions usually are, v1.2.3.4, is left alone.

File hashes

Setting: EnableCyberHash

A run of exactly 32, 40 or 64 hexadecimal digits is read as an MD5, SHA-1 or SHA-256 digest. 44d88612fea8a8f36de82e1278abb02f is the MD5 of the EICAR test file. The panel names the algorithm and the length. A hash is an identity rather than a record, so everything else comes from the datasets: the threat reports CISA advisories, abuse.ch ThreatFox and abuse.ch MalwareBazaar make about it, and any watchlist entry. ed01ebfbc9eb5bbea545af4d01bf5f1071661840480439c6e5babe8e080e41aa is a WannaCry ransomware sample: with malware.tsv installed its hover says Reported malicious and its panel names the family and the file, and it finds the same sample by its MD5 or SHA-1. A hash no dataset knows proves nothing about the file either way.

A 40 digit digest is also the shape of a Git object identifier. The panel says so rather than guessing between the two.

What stays in your message

Several runs sit so close to an indicator that the matcher has to look past them. It matches them and then leaves them in the message, outside the link:

You writeWhat is linkedWhat stays
Patched CVE-2021-44228.The identifierA trailing . , ; : ! or ?
seen at 203.0.113.7:443 twiceThe addressThe port, :443
fe80::a%eth0 on the wireThe addressThe zone, %eth0
md5:44d88612fea8a8f36de82e1278abb02fThe digestThe label, md5:

The md5:, sha1: and sha256: labels are read with either a colon or an equals sign, and the label has to agree with the length. md5: in front of 64 digits is declined outright rather than linked as a SHA-256, because one of the two is wrong and the plugin cannot tell which.

An indicator inside a protected span is left alone as well: a code span, a fenced block, an existing link, an @mention, a ~channel-link or a #hashtag. Mattermost turns each of those into a link of its own, and writing into one would destroy it.

What the panel shows

Clicking an indicator opens the right-hand sidebar. See the sidebar panel for the shared mechanics.

SectionShows
HeadingThe name of the thing, where it has one, over the indicator itself. A vulnerability also carries its score as a badge colored by severity, and a Known exploited badge when the known-exploited list holds it.
SummaryThe description the catalog or the dataset carries. A long one is cut to six lines, with Show more for the rest.
ReadingsThe rows for that kind: scores and dates for a vulnerability, tactics and platforms for a technique, scope and network for an address, the algorithm for a hash.
Vector, decodedThe CVSS vector spelled out one metric to a line, for version 2.0, 3.x and 4.0 vectors: how the flaw is reached, what it needs, and what it costs. The most dangerous value of each metric, such as a Network attack vector or None for privileges required, is marked. A metric the vector leaves undefined is not listed.
WatchlistAny verdict your own watchlist records for this indicator, with its source, note and date.
RelatedLinks to the weaknesses, parents and sub-techniques around it, each one opening the same panel.
Threat reportsFor an address or a file hash, every report a CISA advisory or a threat feed makes about it: the source, linked to its page, the threat in red when it is malicious, and the malware, ports, confidence and dates. A Tor exit is listed as context. The hover card says Reported malicious and counts the sources.
Weakness detailFor a weakness, the whole description in place of its first sentence, then collapsed sections for its background, consequences, mitigations, detection methods and observed examples, each with its count. An observed CVE opens the same panel. Read from the bundled cwedetail.tsv.
ATT&CK detailFor a technique, the whole description, then collapsed sections for its mitigations, its detection analytics with the log sources each reads, its procedure examples, and its references. Mitigations, groups, software, campaigns and citations link out to their pages. A tactic lists its techniques, each opening the same panel. A technique MITRE has revoked names and links its replacement. Read from the bundled attackdetail.tsv.
Affected and referencesCollapsed sections, each with its count: the products and versions as the reporting organization lists them and as NVD configures them, then the references, with vendor advisories and patches first and exploits next. Present only when the vulnerability detail dataset is installed.

The dataset list is on the standalone page.

The page behind an indicator link also lists which datasets are installed and when each was generated, so an empty answer can be told from a missing file. The panel leaves that list out, and ends instead with a Data sources link that opens a table of every file behind that answer and when each was compiled. That is when the file was built, not any date inside it; the embedded ATT&CK and CWE catalogs show when the plugin's copy was generated, and a vendor IP database its own build date.

An agent in the Mattermost Agents plugin can ask the same questions: its lookup_cyber_indicator tool looks up to 25 indicators at once and answers from the same datasets the panel reads, so "is this address malicious?" or "which of these CVEs are known exploited?" gets the answer this page would give. See From an LLM agent, over MCP.

Where the data comes from

Two catalogs are built into the plugin: ATT&CK and CWE. They need no configuration, they are the same on every node, and they are what decides whether an identifier of those two kinds is recognized at all.

Everything else is a file an operator syncs onto the server, into the directory named by CyberDatasetsDir:

FileCarries
cve.tsvVulnerability records: summary, dates, CVSS score and vector, and the weaknesses each one names
cvedetail.tsvAffected products and versions, as the reporting organization lists them and as NVD configures them, the references, and which organization reported each weakness
cwedetail.tsvFor each weakness: its whole description, background, consequences, mitigations, detection methods and observed CVEs. Ships with the plugin
attackdetail.tsvFor each ATT&CK technique and tactic: its whole description, the mitigations and detection strategies MITRE maps to it with their analytics and log sources, every procedure example from a group, malware, tool or campaign, and its references. Ships with the plugin
advisory.tsvThe IP addresses and file hashes named in the CISA advisories the plugin ships with, each linked to its advisory. Ships with the plugin
threat.tsvIP addresses and file hashes reported by abuse.ch ThreatFox and Feodo Tracker, and the Tor exit list, with the malware, ports, confidence and dates each feed gives. Never shipped: abuse.ch's terms may require a subscription for commercial use, so an operator fetches it under their own terms
malware.tsvEvery malware sample in abuse.ch MalwareBazaar, found by its SHA-256, MD5 or SHA-1, with its file name, file type, malware family and the date it was first seen. Never shipped, under the same terms as threat.tsv
epss.tsvExploit prediction scores and percentiles
kev.tsvThe known exploited vulnerabilities catalog, with its due dates and required actions
ip.tsvAutonomous system, country, region and city per address range
watchlist.tsvYour own verdicts, for any indicator of any kind
Any .mmdbA vendor IP database in MaxMind's format, read alongside ip.tsv; the one that gives an address a region and city. None ships with the plugin. DB-IP's free IP to City Lite database works and is licensed CC BY 4.0; MaxMind's GeoLite2 and paid databases work too. When DB-IP or GeoLite2 data answers, the panel, the page and the hover card credit the vendor, as both licenses require, and the panel and page link back to it

kev.tsv, cwedetail.tsv and attackdetail.tsv are small enough to ship inside the bundle, and a file of the same name in the configured directory replaces the bundled one. Both are snapshots, stamped with the catalog they were built from. Remove one and the panel says that dataset is not installed rather than implying the indicator is not in it. That distinction is deliberate, and it is why each sentence names the dataset it is talking about.

Nothing is ever fetched from the internet.

Every answer comes from a file on this server, which is why an air-gapped install behaves exactly as a connected one does. It also means the enrichment is only as current as the last sync, and the panel's Data sources table says when each file was compiled so a reader can judge that for themselves.

A file dropped into the directory is picked up within a few seconds, with no restart and no configuration change. Removing one is noticed the same way, and the panel goes back to saying that dataset is not installed.

A dataset may also be dropped in gzipped, as cve.tsv.gz, which is how the release publishes them: the full vulnerability dataset is 40 MB gzipped and 186 MB unpacked. The plugin unpacks it once into cve.tsv in the same directory and reads that, because it searches a dataset in place and cannot do that inside an archive. It unpacks again only when a different archive replaces the first, and a damaged archive never replaces a good file. The directory must be writable by the Mattermost server for this; on read-only media, run gunzip -k yourself and drop in the result.

A dataset whose schema stamp is absent or wrong is skipped.

Every file carries a stamp naming the schema it was built for. One that carries none, or names another, is skipped rather than misread, and the reason is logged once as TF-21002. Skipping is per file: every other dataset still answers.
